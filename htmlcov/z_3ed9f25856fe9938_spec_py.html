16"""Build the ``run-python`` pt-archiver spec for the Archives app. 

17 

18:func:`build_archives_spec` is the pure ``(form, resolved) -> RunPythonSpec`` 

19builder fed to the framework's three-phase create path (and reused by the legacy 

20Jinja form path via ``deps``), so an archive task's payload is byte-identical 

21regardless of the call origin. It serialises the kept 

22``PurgeConfig`` / ``PurgeConfigAll`` / ``PurgeConfigItem`` validators to the YAML 

23config, sourcing the schema / table / destination names from the entities 

24``resolve_refs`` already fetched (falling back to the free-typed value for an 

25``allow_custom`` selection). The framework's ``assemble_envelope`` supplies the 

26executor ``target``, ``_service_name``, and the connectivity meta around this 

27spec; ``extra_meta`` carries the source node name as ``_pmm_node_name``. 

28"""
