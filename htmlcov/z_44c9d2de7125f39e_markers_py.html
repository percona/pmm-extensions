16"""Declare the annotation markers and layout objects of the model-first form DSL. 

17 

18The markers (:class:`Ui`, the four reference types, :class:`Requires`, 

19:class:`Forbidden`, :class:`Choices`, :class:`Hidden`) are small frozen 

20dataclasses placed in a field's ``Annotated[...]`` and read back from 

21:attr:`pydantic.fields.FieldInfo.metadata`. Pydantic preserves objects it does 

22not recognise as constraints in that list and ignores them during validation, 

23so they ride along on the create model without affecting what the server 

24accepts. The markers must sit at the **outer** ``Annotated`` level wrapping the 

25full field type — ``Annotated[int | None, SchemaRef(...), Ui(...)]`` — because a 

26marker nested inside a union member (``Annotated[int, SchemaRef(...)] | None``) 

27stays buried in the annotation and never reaches ``FieldInfo.metadata``. 

28 

29The layout objects (:class:`SectionLayout`, :class:`FormLayout`, 

30:class:`SectionRules`, :class:`FormRules`) are ordinary objects passed to the 

31derivation functions, not annotation metadata. 

32"""

96@dataclass(frozen=True, slots=True, kw_only=True) 

97class Ui: 

98 """Carry a field's presentation metadata; never validation semantics. 

99 

100 Removing any attribute here cannot change what the server accepts (the 

101 create model's own type governs that), so per the DSL's governing rule 

102 presentation extras belong on ``Ui`` while gates live in separate 

103 :class:`Requires` / :class:`Forbidden` markers. 

104 

105 :param label: The human-readable field label. Optional; when omitted, 

106 derived from the field name at consumption (underscores replaced by 

107 spaces and title-cased). Supply an explicit label only when it diverges 

108 from that default. 

109 :param section: The layout-section key the field belongs to; must match a 

110 :attr:`SectionLayout.key` in the form layout. 

111 :param description: Optional helper text rendered beneath the field. 

112 :param destructive: Opt-in notice that *setting or enabling* this field 

113 causes irreversible loss — of user data, or of operator-managed state 

114 such as a hand-tuned configuration file; the value is the consequence 

115 sentence a confirmation surfaces. Presence is the mark — deliberately 

116 one string rather than the ``disabled`` / ``disabled_reason`` pair used 

117 by :class:`Option`, because a field marked destructive with no text 

118 gives a renderer nothing to show, and one attribute makes that state 

119 unrepresentable rather than merely invalid. A blank or whitespace-only 

120 value is rejected at construction. Defaults to ``None`` (unmarked). 

121 :param depends_on: For a cascade reference (``SchemaRef`` / ``TableRef`` / 

122 ``HostRef``) or a :class:`RemoteChoices` field, the field name whose 

123 value drives this field's options or default selection. Required for 

124 ``SchemaRef`` / ``TableRef``; optional for ``HostRef`` (when set on a 

125 single-value host field, the renderer auto-selects an executor from the 

126 upstream service; multi-host ignores it) and for ``RemoteChoices`` (when 

127 set, the fetch is parameterised by the dependency's value and the field 

128 stays disabled until it is set, unless the marker's ``allow_custom`` 

129 keeps free-text entry open). Ignored for other field kinds. Defaults 

130 to ``None``. 

131 :param order: Sort position within the section; ties break on declaration 

132 order. Defaults to ``0``. 

133 :param required: Override for the wire ``required`` flag. ``None`` (the 

134 default) derives it from whether the model field has a default; set it 

135 when a field carries a default yet must still render as required. 

136 :param widget: Optional widget override for cases the base type cannot 

137 express (multi-line text, YAML, an int/str choice). Defaults to 

138 ``None`` (infer from the annotation). 

139 :param default: Tri-state form-display default for the derived schema field, 

140 distinct from the model/runtime default. Unset (the :data:`_UNSET` 

141 sentinel, the default) derives the schema default from the Pydantic field 

142 default; ``None`` sets the form default to ``None``; any other value sets 

143 the form default to that value. The model's own default — what the JSON 

144 body validates against — is never affected. 

145 :param help_placement: Where the renderer shows this field's 

146 ``description``. ``"inline"`` puts it under the input, where a format 

147 hint belongs — visible while someone types into the field it describes. 

148 ``"tooltip"`` puts it behind a help icon beside the label, which keeps 

149 prose from dominating a form that has a lot of it. ``None`` (the 

150 default) lets the renderer decide by length: a description that fits 

151 roughly one line renders inline, a longer one goes behind the icon. Set 

152 it only where that default reads wrong. Reference and selector fields 

153 ignore it and are always inline — their label is a plain string the 

154 renderer also uses in validation messages, so there is no node to hang 

155 an icon from. Defaults to ``None``. 

156 :param parent: Name of a sibling ``bool`` field, in the same section, that 

157 this field parameterises. The renderer draws the field indented beneath 

158 that toggle and keeps it non-interactive until the toggle is on, rather 

159 than hiding it, so a reader can see what enabling the toggle will offer. 

160 Presentation only, per this class's governing rule: it changes nothing 

161 about what the server accepts. A field that must also be *rejected* 

162 while its toggle is off says so with its own ``Forbidden``, which is a 

163 per-field validation decision rather than something the pointer 

164 implies. 

165 :func:`~app.extensions.apps.framework.form_dsl.derivation.derive_form_sections` 

166 checks only that the target is a same-section ``bool`` that is not 

167 itself parented. Defaults to ``None``. 

168 """

171 section: str

218@dataclass(frozen=True, slots=True) 

219class ArgFormat: 

220 """Map a field to a CLI argument via a ``${value}`` template. 

221 

222 Mirrors the ``${value}`` convention used by snippet parameter metadata. A 

223 *value* arg's template contains ``${value}`` and is emitted — with the field 

224 value shlex-quoted and substituted in — only when the field value is truthy. 

225 A *flag* arg's template omits ``${value}`` and is emitted verbatim only when 

226 the field value is ``True``. The marker is read back from the field's 

227 ``FieldInfo.metadata`` to assemble the run-command argument string; the 

228 presence of ``${value}`` is itself the value-vs-flag discriminator, so no 

229 separate flag attribute is needed. 

230 

231 Leaving ``template`` unset derives it from the field name and type — a 

232 non-``bool`` field becomes the value arg ``--<kebab-field-name>=${value}`` and 

233 a ``bool`` field becomes the flag ``--<kebab-field-name>`` — so a field carries 

234 an explicit template only when its CLI spelling diverges from its name (a 

235 ``bool`` ``explain_arg`` field whose flag is ``--explain``, say). 

236 

237 :param template: The argument template — ``"--databases=${value}"`` for a 

238 value arg or ``"--binary-index"`` for a flag. Defaults to ``None``, which 

239 derives ``--<kebab-field-name>=${value}`` for a non-``bool`` field and 

240 ``--<kebab-field-name>`` for a ``bool`` field. 

241 """ 

242 

243 template: str | None = None

476@dataclass(frozen=True, slots=True) 

477class RemoteChoices: 

478 """Mark a field whose options are fetched at render from an app endpoint. 

479 

480 Unlike :class:`Choices` (static options embedded in the wire), the options 

481 are fetched at render time from ``endpoint``, which must return a 

482 ``Choice``-compatible list (``value``, ``label``, optional ``disabled`` / 

483 ``disabled_reason``). An optional cascade is declared via 

484 ``Ui(depends_on=...)`` — when set, the fetch is parameterised by the 

485 dependency's value (passed as a query parameter named after the 

486 ``depends_on`` field) and the field lists no options until the dependency is 

487 set, mirroring :class:`SchemaRef` / :class:`TableRef`; it also stays disabled 

488 while it waits unless ``allow_custom`` keeps free-text entry open. When 

489 ``depends_on`` is omitted the field fetches once with no cascade (mirroring 

490 the optional cascade of :class:`HostRef`). 

491 

492 The annotation must accept ``str``, since a set value (a fetched option's 

493 ``value`` or a free-typed custom value) reaches the model as a string. An 

494 **optional** field must additionally accept ``None``, because the selector 

495 commits ``null`` both when the user clears it and — unprompted — when its 

496 cascade parent changes; declare those as ``str | None = None``. A required 

497 field may stay a bare ``str``: the renderer blocks the submit rather than 

498 sending the ``null``. Derivation rejects either mismatch, so a schema that 

499 builds cannot 422 on the value its own selector commits. 

500 

501 :param endpoint: The fully-resolved path the renderer fetches options from, 

502 relative to the frontend ``apiClient`` base (``/api``). Bake any 

503 app-specific path segments here at schema-build time (e.g. 

504 ``/apps/<app_key>/<sub>/<resource>``) rather than templating client-side. 

505 

506 .. note:: 

507 On a ``TaskExecutionApp`` with the default ``capabilities.detail``, 

508 ``build_router`` mounts the greedy ``GET /{detail_path_param}`` 

509 before ``extra_routes``, so a **single-segment** sibling path (e.g. 

510 ``/apps/<key>/choices``) will be swallowed by the detail route and 

511 return 404. Use at least two path segments after the app prefix 

512 (e.g. ``/apps/<key>/backups/choices``) to avoid the collision. 

513 :param allow_custom: When ``True``, the field also accepts a free-typed 

514 value alongside the fetched options and emits ``allow_custom`` on the 

515 wire. Defaults to ``False``. 

516 """ 

517 

518 endpoint: str 

519 allow_custom: bool = False 

520 

521 def __post_init__(self) -> None: 

522 """Reject an empty endpoint so the wire never advertises an unfetchable source.""" 

523 if not self.endpoint.strip(): 

524 raise ValueError("RemoteChoices endpoint must be a non-empty path")

560 renderer shows it beneath the heading, but a renderer may omit it, 

561 so do not put guidance here that a user must see. Defaults to 

562 ``None``. 

563 :param advanced: Whether the section holds expert options rather than the 

564 common case. The renderer withholds advanced sections behind a single 

565 "Show advanced options" control placed after the ordinary ones, and 

566 reveals them as ordinary top-level sections — so a form with several 

567 expert sections costs one row at rest instead of one per section. It 

568 reveals them on its own, and expands the section concerned, whenever 

569 one holds a value other than its default or a field an error points 

570 into. Membership needs no adjacency: the renderer collects them 

571 wherever they appear, preserving order. A single reveal bucket is 

572 deliberate: a titled group shell would nest one disclosure inside 

573 another, and a second reveal control on the same form is the 

574 progressive-disclosure pattern it exists to avoid. A custom control 

575 label, if a form ever needs one, is an additive ``FormLayout``-level 

576 addition rather than a change to this flag. Defaults to ``False``. 

577 :param collapsible: Whether the renderer may collapse the section. Defaults 

578 to ``False``. 

579 :param collapsed_by_default: Whether a collapsible section starts collapsed. 

580 Defaults to ``False``. 

581 :param render_after_submit: Whether the section renders after the submit 

582 button. Defaults to ``False``. 

583 :param forbidden: Optional whole-section hide gates copied verbatim to 

584 :attr:`~app.extensions.apps.framework.schema.FormSection.forbidden`. This is 

585 a presentation gate, not a runtime rule. Defaults to ``None``. 

586 """
