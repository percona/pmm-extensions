16"""Define the OpenManager Inventory persistence models. 

17 

18Three tables, and the split between them is the design: 

19 

20``om.om_host`` and ``om.om_service`` 

21 What the estate *is*, one row per entity, upserted. A host row exists whether or 

22 not any MongoDB was found on it, which is what makes "which pmm-clients have no 

23 database" answerable at all — and it is not hypothetical: the sandbox carries 

24 hosts with a PMM client and nothing else beside arbiters running a mongod PMM has 

25 no service for, and PMM's inventory describes the two identically. 

26 

27``om.om_inventory_run`` 

28 What one sweep *did*. A receipt, not a copy of the estate: which entity was 

29 attempted, on which executor host, whether it answered, and any error. Keeping 

30 the collected attributes out of it is load-bearing — with ``RUN_RETENTION`` 

31 runs kept, putting them here stores the same facts that many times over, and 

32 creates a second source of truth for them. 

33 

34Each entity carries a few real columns for identity and freshness plus one JSONB 

35document of everything probed, so changing what is collected is a payload change 

36rather than a migration. The cost is that fleet-wide questions become JSONB queries; 

37promoting a field to a column later is easy and the reverse is not. 

38 

39This module is loaded by Alembic through ``spec_from_file_location`` without running 

40the package ``__init__``, so it must not import sibling app modules. That is also why 

41the schema below is a bare string rather than 

42``app.extensions.apps.shared.om.config.OM_SCHEMA_SYMBOL``: the token has to be spelled here, 

43and ``sqlalchemy_celery_beat`` makes the same trade with ``celery_schema``. 

44"""

62#: The symbolic schema every table here declares. See the module docstring for why it 

63#: is spelled rather than imported. 

64OM_SCHEMA = "om_schema" 

65 

66# Table names carry an ``om_`` prefix — ``om_host``, ``om_service``, 

67# ``om_inventory_run`` — on top of the ``om`` schema that already qualifies them, 

68# which looks redundant until the schema stops actually separating anything. 

69# ``om.om_service`` would be a different table from PMM Extensions inventory's bare ``service`` 

70# even without the prefix wherever schemas are real: on PostgreSQL in production, and 

71# on SQLite once the root conftest gives each connection a real ``om`` schema via 

72# ``ATTACH``. But the real-PostgreSQL test lane translates *every* declared schema 

73# token — ``om_schema`` included — into the same single per-worker schema for 

74# teardown simplicity, which collapses ``om_schema.service`` onto 

75# ``None.service`` and makes them the same physical table. That is not hypothetical 

76# either: it produced a ``CREATE TABLE`` emitted twice for one name, the second call 

77# failing as a duplicate, the first time this app's tables were ever exercised against 

78# a real, non-SQLite database. The prefix survives being redundant under schemas 

79# because it is the one thing that holds even when schemas do not.

82def _observed_document_type() -> Any: 

83 """Build the column type for an ``observed`` document. 

84 

85 A fresh type instance per call. A single shared ``Column`` cannot be reused across 

86 two models — SQLAlchemy binds a Column to exactly one Table — which is why the 

87 freshness mixin below declares types rather than columns. 

88 

89 :return: ``JSONB`` on PostgreSQL, plain ``JSON`` everywhere else: ``JSON`` is the 

90 correct default to carve a variant *out of*, since PostgreSQL is the odd one 

91 with a dedicated binary type. 

92 """ 

93 return JSON().with_variant(postgresql.JSONB(astext_type=Text()), "postgresql")

96class ProbeRunStatus(StrEnum): # rst-literal-ok: "None answered" is the English word 

97 """Enumerate the states of one probe sweep. 

98 

99 ``PARTIAL`` is the common steady state, not an alarm: the probe reaches only 

100 services whose node runs a healthy ``raw_exec`` executor, and an inventory row 

101 routinely outlives the executor that served it. 

102 

103 :cvar RUNNING: The sweep is in flight. 

104 :cvar SUCCESS: Every service that resolved to a live executor answered. 

105 :cvar PARTIAL: Some answered, some did not. 

106 :cvar FAILED: None answered, or the sweep raised. 

107 :cvar SKIPPED: Refused before doing any work, because another sweep already held 

108 the hosts it would have covered or because ``ENABLED`` was off. Recorded rather than skipped silently: a 

109 scheduled sweep that quietly does nothing leaves a ten-minute gap in the 

110 history that reads exactly like the schedule having fired and found nothing. 

111 """ 

112 

113 RUNNING = "running" 

114 SUCCESS = "success" 

115 PARTIAL = "partial" 

116 FAILED = "failed" 

117 SKIPPED = "skipped"

137class ObservedEntity(SQLModel): 

138 """Carry the columns every probed entity has, whatever it is. 

139 

140 Not a table: a mixin, so the two entity tables cannot drift apart on 

141 the freshness rules. Each field declares a *type* rather than a ``Column``, 

142 because a Column instance binds to exactly one Table and sharing one across two 

143 models fails at import. 

144 

145 Deliberately **not** :class:`~app.core.db.models.BaseSQLModel`: that base 

146 mandates an auto-incrementing integer ``id`` as the primary key, and both 

147 tables here are keyed on a natural id PMM already assigns (``node_id`` / 

148 ``service_id`` on :class:`OmHost` / :class:`OmService`) so a row can be 

149 looked up by the same id every other caller already has, with nothing to 

150 translate. A second, unused surrogate ``id`` column would only invite a 

151 query that joins on the wrong one. ``updated_at`` is declared here instead 

152 of inherited for the same reason: :class:`~app.core.db.models.BaseSQLModel` 

153 pairs it with a database-managed ``created_at`` this mixin has no use for — 

154 ``first_seen_at`` already is that column, under the name the freshness 

155 lifecycle uses elsewhere on this class. 

156 

157 The lifecycle these implement is four rules, each cheap now and expensive to 

158 discover later: 

159 

160 * ``failing_since`` is set with ``COALESCE(failing_since, now())`` — overwrite it 

161 on every failure and "since" quietly becomes "most recent failure", so the 

162 duration is always about one schedule interval and the column is worthless; 

163 * a failed probe must **not** erase ``observed``. The last known good document is 

164 kept with its own ``collected_at``, because what a host was running when last 

165 seen is exactly what is wanted while it is unreachable; 

166 * only a run that actually attempted an entity touches its timestamps, so a 

167 single-host refresh does not mark everything it skipped as failed; 

168 * the upsert lists the columns it owns explicitly. Nothing here is user-writable 

169 *yet*, so there is nothing to clobber — but a blanket ``ON CONFLICT DO UPDATE`` 

170 over every column wipes the first field that ever is. 

171 

172 :param observed: Everything the probe collected, with its own ``collected_at``. 

173 Non-nullable with a ``{}`` default rather than nullable: PMM Extensions' ``AutoJSON`` 

174 stores a Python ``None`` as the JSON scalar ``null``, so "never probed" and 

175 "probed, found nothing" would be indistinguishable. 

176 :param first_seen_at: When OM first wrote a row for this entity. 

177 :param last_attempt_at: When a run last targeted it. Not "when a run last ran". 

178 :param last_success_at: When it last answered. This is the data's age. 

179 :param failing_since: The **first** failure after the last success, so the column 

180 says "failing for three days" rather than "failed a minute ago". ``None`` 

181 while healthy. 

182 :param consecutive_failures: Failures since the last success. 

183 :param last_error: The most recent failure detail. 

184 :param last_run_id: The run that last attempted it, for joining to the receipt. 

185 :param updated_at: When this row last changed. 

186 """ 

187 

188 observed: dict[str, Any] = SQLField( 

189 default_factory=dict, 

190 sa_type=_observed_document_type(), 

191 nullable=False, 

192 # Parenthesised rather than bare: on both dialects PMM Extensions runs the parentheses 

193 # are ordinary grouping, so this resolves to the same ``{}`` default either 

194 # way and there is nothing to gain by unwrapping it. 

195 sa_column_kwargs={"server_default": text("('{}')")}, 

196 ) 

197 first_seen_at: UTCDatetime = SQLField( 

198 default_factory=utc_now, sa_type=DateTimeWithTimezone, nullable=False 

199 ) 

200 last_attempt_at: UTCDatetime | None = SQLField( 

201 default=None, sa_type=DateTimeWithTimezone 

202 ) 

203 last_success_at: UTCDatetime | None = SQLField( 

204 default=None, sa_type=DateTimeWithTimezone 

205 ) 

206 failing_since: UTCDatetime | None = SQLField( 

207 default=None, sa_type=DateTimeWithTimezone 

208 ) 

209 consecutive_failures: int = SQLField(default=0, nullable=False) 

210 last_error: str | None = SQLField(default=None) 

211 last_run_id: UUID | None = SQLField(default=None) 

212 updated_at: UTCDatetime = SQLField( 

213 default_factory=utc_now, sa_type=DateTimeWithTimezone, nullable=False 

214 )

217class OmHost(ObservedEntity, table=True): 

218 """Record one host, whether or not a database was found on it. 

219 

220 Keyed on **PMM's** node id. OM is not the system of record for identity here, 

221 PMM is, so the table and the API speak the id every consumer already holds and 

222 nothing needs translating anywhere — including the scoped refresh, which takes 

223 the ``node_id`` PMM already has. 

224 

225 Plain ``str``, not ``uuid``: PMM's ids are usually UUIDs but not always. The PMM 

226 server's own node is the literal string ``pmm-server`` in every deployment, and a 

227 ``uuid`` column would reject the one node every installation has. Left as SQLModel's 

228 inferred ``AutoString`` rather than pinned to ``sa_type=Text``: it is what SQLModel 

229 gives a ``str`` primary key, it stays unbounded on both dialects PMM Extensions runs, and it is 

230 the same type :attr:`app.inventory.models.NodeBase.external_id` carries for its own 

231 external identifier. 

232 

233 The consequence to accept openly is that if PMM re-registers a node under a new 

234 id, OM gets a second row and the old one stays — there is no host retention, only 

235 ``DELETE /hosts/{node_id}`` removes it. The usual answer — a OM-minted id plus a 

236 natural key to recognise the machine across ids — has no natural key available: 

237 ``machine_id`` is inherited from the container image, so most of this sandbox 

238 reports one shared value and the rest report an empty string. Matching on it would 

239 merge unrelated hosts. Hence no surrogate key: it would only move the guess into a 

240 matching function. 

241 

242 Class named ``OmHost`` rather than ``Host``, and the table ``om_host`` rather 

243 than bare ``host``: SQLModel keeps one registry for the whole application and 

244 it already carries ``app.inventory.models.Service``, so the short class name 

245 is genuinely taken — and that table is also named plain ``service`` with no 

246 schema of its own (``schema=None``), which OM's ``service`` would collide with 

247 the moment anything collapses schemas into one physical namespace, as the 

248 real-PostgreSQL test lane deliberately does for worker isolation. 

249 Prefixing both avoids the class collision and the table collision the same 

250 way. The pair is kept symmetrical. 

251 

252 :param node_id: PMM's node id, the primary key. 

253 :param name: The node's registered name. 

254 :param address: The node's registered address. 

255 :param executor_host: The Nomad client that serves it, ``None`` when none does. 

256 """ 

257 

258 __tablename__ = "om_host" 

259 __table_args__ = ( 

260 # Partial: the healthy majority is not in the index at all. Expressed here 

261 # rather than with ``index=True`` because a ``WHERE`` clause cannot be, and 

262 # OM's migrations are hand-written anyway (autogenerate is off for them). 

263 Index( 

264 "ix_om_host_failing_since", 

265 "failing_since", 

266 postgresql_where=text("failing_since IS NOT NULL"), 

267 ), 

268 {"schema": OM_SCHEMA}, 

269 ) 

270 

271 node_id: str = SQLField(primary_key=True) 

272 name: str = SQLField(sa_type=Text, nullable=False) 

273 address: str | None = SQLField(default=None, sa_type=Text) 

274 executor_host: str | None = SQLField(default=None, sa_type=Text)

277class OmService(ObservedEntity, table=True): 

278 """Record one MongoDB service PMM has registered, on its host. 

279 

280 A service row is a service **PMM knows** — that is what keying on ``service_id`` 

281 means. The probe will still find mongod processes PMM has no service for, and 

282 those are recorded on the host's ``observed`` document instead: no identity to 

283 invent, no schema commitment, and the estate view does not get to claim the host 

284 is empty when it is not. Arbiters are the reason that case is normal rather than 

285 exotic: one holds no data, therefore no user documents, therefore SCRAM cannot 

286 authenticate, therefore ``pmm-admin add mongodb`` fails for it. 

287 

288 The foreign key is safe because both tables belong to *this* app. Across apps the 

289 ``om`` schema takes no foreign keys at all: each app that owns migrations is an 

290 independent branch, an image that strips an app removes its ``versions/`` 

291 directory, and there is no guaranteed ordering between branches — so an FK into 

292 another app's table can reference something that legitimately vanishes. 

293 

294 :param service_id: PMM's service id, the primary key. Plain ``str`` for the same 

295 reason as :attr:`OmHost.node_id`, including the ``AutoString`` inference. 

296 :param node_id: The host it runs on. 

297 :param name: The service name as PMM registered it. 

298 :param port: The port it listens on. 

299 :param role: What the probe found it to be — ``mongod``, ``mongos``, ``config``, 

300 ``arbiter``. Observed, not declared: plain text rather than an enum, because a 

301 role we have not thought of should land in the column rather than raise. (An 

302 enum would also need care: SQLAlchemy's non-native ``Enum`` persists by member 

303 *name*, so a CHECK constraint listing lowercase values rejects every insert.) 

304 """ 

305 

306 __tablename__ = "om_service" 

307 __table_args__ = ( 

308 # Named rather than left to ``index=True``, which derives the name from the 

309 # *declared* table — and the declared schema is the symbolic token, so the 

310 # index would ship into the real ``om`` schema called 

311 # ``ix_om_schema_service_node_id``. 

312 Index("ix_om_service_node_id", "node_id"), 

313 {"schema": OM_SCHEMA}, 

314 ) 

315 

316 service_id: str = SQLField(primary_key=True) 

317 node_id: str = SQLField( 

318 sa_column=Column( 

319 AutoString(), 

320 # Qualified with the symbolic schema: the FK target is resolved against 

321 # the *declared* name, and the connection translates both sides together. 

322 # AutoString, not Text: this column carries ix_om_service_node_id, and 

323 # matches the AutoString primary key it references on om_host. 

324 ForeignKey(f"{OM_SCHEMA}.om_host.node_id", ondelete="CASCADE"), 

325 nullable=False, 

326 ) 

327 ) 

328 name: str | None = SQLField(default=None, sa_type=Text) 

329 port: int | None = SQLField(default=None) 

330 role: str | None = SQLField(default=None, sa_type=Text)

333class ProbeRun(BaseUUIDSQLModel, table=True): 

334 """Record one probe sweep: which hosts it attempted, and what came of it. 

335 

336 A receipt, not a copy of the estate. What the probe *found* lives on 

337 :class:`OmHost` and :class:`OmService`, upserted and current; this table only 

338 says which entity was attempted, on which executor host, whether it answered, 

339 how long it took and what failed. Keeping the collected attributes out of it is 

340 load-bearing — with ``RUN_RETENTION`` runs kept, putting them here would store 

341 the same facts that many times over and create a second source of truth for them. 

342 

343 :param started_at: When the sweep began. 

344 :param finished_at: When it reached a terminal status; ``None`` while running. 

345 :param status: The sweep's lifecycle state. 

346 :param services_total: MongoDB services inventory reported. 

347 :param services_resolved: ...of which mapped to a live executor host. 

348 :param services_orphaned: ...of which did not. Not an error. 

349 :param services_answered: Services that returned a usable probe record. 

350 :param hosts_total: Hosts in scope this sweep, service or no service. 

351 :param hosts_probeable: ...of which had a usable executor to dispatch to. The 

352 difference from ``hosts_total`` is the estate nothing can be run on, which is 

353 a fact about onboarding rather than a failure of the sweep. 

354 :param hosts_answered: Hosts that returned a usable record. 

355 :param nodes: One record per host: where it was probed, how that host was 

356 matched, whether it answered, how long it took, and its dispatch's task 

357 history id — so a reader can still open the probe's raw output, which the 

358 receipt itself does not carry. The counters above are this list's summary, 

359 and a summary is all a sweep could show until this column existed — "5 of 14 

360 answered" cannot say *which* five, on which hosts, or which one took a 

361 minute. 

362 :param scope: The node ids this run was asked to refresh, or ``None`` for the 

363 whole estate. Stored rather than inferred, because without it the receipt 

364 cannot be read honestly — "9 of 13 answered" means something different when 

365 the run was only ever asked about one host — and because the single-flight 

366 guard has nothing to compare against. 

367 :param error: The failure detail when the sweep itself raised. 

368 """ 

369 

370 __tablename__ = "om_inventory_run" 

371 # A *symbolic* schema, translated per bind by the engine 

372 # (``app/extensions/apps/shared/om/config.py``). Never a literal: SQLite has no schemas, so a real 

373 # name here would make the table uncreatable in the unit suite, and the 

374 # real-PostgreSQL lane routes every table into a per-xdist-worker schema that a 

375 # hard-coded ``om`` would escape and then collide across workers. 

376 __table_args__ = ( 

377 # Named for the same reason OmService names its index: ``index=True`` 

378 # derives the name from the declared table, schema token included. 

379 Index("ix_om_inventory_run_started_at", "started_at"), 

380 Index("ix_om_inventory_run_status", "status"), 

381 {"schema": OM_SCHEMA}, 

382 ) 

383 

384 started_at: UTCDatetime = SQLField( 

385 sa_type=DateTimeWithTimezone, default_factory=utc_now 

386 ) 

387 finished_at: UTCDatetime | None = SQLField( 

388 default=None, sa_type=DateTimeWithTimezone 

389 ) 

390 status: ProbeRunStatus = SQLField( 

391 default=ProbeRunStatus.RUNNING, 

392 sa_column=Column( 

393 EnumField(ProbeRunStatus, native_enum=False, create_constraint=True), 

394 nullable=False, 

395 ), 

396 ) 

397 

398 services_total: int = SQLField(default=0) 

399 services_resolved: int = SQLField(default=0) 

400 services_orphaned: int = SQLField(default=0) 

401 services_answered: int = SQLField(default=0) 

402 

403 # A sweep attempts hosts as well as services, and has since a host became 

404 # probeable for its own sake. Counting only services made a refresh of a 

405 # pmm-client host with no database read as "0 of 0", which is indistinguishable 

406 # from a run that did nothing. 

407 hosts_total: int = SQLField(default=0) 

408 hosts_probeable: int = SQLField(default=0) 

409 hosts_answered: int = SQLField(default=0) 

410 

411 # Explicit JSONB rather than ``AutoJSON``: the latter silently drops 

412 # ``none_as_null`` on PostgreSQL, so a Python ``None`` lands as the JSON scalar 

413 # ``null`` and a caller cannot tell "no nodes" from "the column was never set". 

414 # A run reads its nodes all at once or not at all, and a per-node table would 

415 # need its own retention story on top of the run's. ``JSON`` is the base type 

416 # here, not ``postgresql.JSONB``: PostgreSQL is the dialect that gets a variant 

417 # carved out of it, rather than the default every other dialect is made to 

418 # carve SQLite out of. 

419 nodes: list[dict[str, Any]] = SQLField( 

420 default_factory=list, 

421 sa_column=Column( 

422 JSON().with_variant(postgresql.JSONB(astext_type=Text()), "postgresql"), 

423 nullable=False, 

424 # Parenthesised rather than bare, like ObservedEntity.observed's own 

425 # server_default: the parentheses are ordinary grouping and resolve to 

426 # the same [] default. 

427 server_default=text("('[]')"), 

428 ), 

429 ) 

430 # The one nullable JSON column in this app, and it needs ``none_as_null`` to be 

431 # honest about it. SQLAlchemy's JSON types default to storing a Python ``None`` as 

432 # the JSON scalar ``null``, so without this a full-estate run is written as 

433 # ``'null'::jsonb`` and `WHERE scope IS NULL` finds none of them — the Python side 

434 # reads back ``None`` either way, so nothing complains until someone asks the 

435 # database which runs were full sweeps. Measured happening before it was set. 

436 # ``none_as_null`` is set on both the ``JSON`` base and the ``JSONB`` variant, for 

437 # the same reason ``nodes`` above inverts which dialect is the default. 

438 scope: list[str] | None = SQLField( 

439 default=None, 

440 sa_column=Column( 

441 JSON(none_as_null=True).with_variant( 

442 postgresql.JSONB(astext_type=Text(), none_as_null=True), "postgresql" 

443 ), 

444 nullable=True, 

445 ), 

446 ) 

447 error: str | None = SQLField(default=None)

522class ProbeNode(BaseModel): 

523 """Report one **host** this sweep attempted, and what came of it. 

524 

525 Host-oriented, because a sweep attempts hosts. A flat list of services — which 

526 this was — cannot show a machine carrying a PMM client and no database, however 

527 many times it is probed, and that machine is the case OM most exists to describe. 

528 

529 One dispatch covers every service on a host, so the host owns the timing and the 

530 failure and its services carry only what is theirs. Previously the duration was 

531 repeated identically across a host's services, which read as several measurements 

532 when it was one. 

533 

534 :param node_id: **PMM's** node id, the key OM holds this host under. 

535 :param host_name: The node's registered name. 

536 :param executor_host: The client its probe ran on; ``None`` when none matched. 

537 :param resolution: ``name`` / ``address`` / ``orphaned`` — how that client was 

538 matched, or that it was not. Orphaned is why nothing ran, not an error. 

539 :param answered: Whether the *host* returned a record. A different question from 

540 whether its services did: a host with no database answers perfectly well and 

541 has no services at all. 

542 :param duration_seconds: The host's wall-clock, dispatch to collected output. 

543 :param task_history_id: The dispatch's task history id, so a reader can open the 

544 probe's raw output. ``None`` when the dispatch never got one back. 

545 :param error: The host-level failure, when its probe failed. 

546 :param services: The services on it, empty when there are none. 

547 """ 

548 

549 node_id: str 

550 host_name: str | None = None 

551 executor_host: str | None = None 

552 resolution: str 

553 answered: bool = False 

554 duration_seconds: float | None = None 

555 task_history_id: int | None = None 

556 error: str | None = None 

557 services: list[ProbeNodeService] = Field(default_factory=list)
