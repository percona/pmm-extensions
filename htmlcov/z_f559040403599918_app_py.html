16"""Wire the PostgreSQL Backups plugin as a declarative ``TaskExecutionApp``. 

17 

18This definition replaces the hand-written JSON API router and schema: the 

19registry discovers the exported ``app`` and mounts its derived router, which 

20serves the schema, list, detail, create, execute, and delete surfaces, plus a 

21net-new ``PUT /{task_name}`` update route. The derived ``GET /schema`` matches 

22the legacy one except that it now surfaces the stanza name validation pattern, 

23which the legacy hand-written schema enforced server-side only. Create and update are 

24derived from the model-first 

25:class:`~app.extensions.apps.backup_pg.models.BackupPgForm` through the ``run-python`` 

26pgBackRest spec builder, with the YAML-config-derived 

27:func:`~app.extensions.apps.backup_pg.deps.build_backup_pg_api_task_response` / 

28:func:`~app.extensions.apps.backup_pg.deps.build_backup_pg_api_detail_response` 

29stamping ``hostname`` / ``backup_type`` (and ``host`` / ``port`` on detail) so 

30the list, detail, create, and update bodies stay byte-identical. The derived PUT 

31and DELETE carry the framework's default protected-task + running-conflict 

32guards; only the body-reading create running-conflict guard rides explicitly via 

33``create_extra_deps``. 

34"""
