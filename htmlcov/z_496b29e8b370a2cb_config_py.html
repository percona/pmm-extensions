16"""Define the OpenManager Inventory settings section. 

17 

18Read straight off YAML/env under ``EXTENSIONS.OM_INVENTORY`` rather than mounted as a field

43class OmInventorySettings(BaseYamlSettings): 

44 """Configure the on-host probe. 

45 

46 The defaults assume the consumer is PMM reading the estate, which serves whatever 

47 each row last reported. That is why ``SCHEDULE`` matters more here than it does for 

48 a job someone triggers by hand: nothing else refreshes a row, and a puller must 

49 never be the thing that waits for a Nomad job. 

50 

51 Every field is ``hot_field`` except ``CREDENTIALS_PATH``, which stays YAML/env only 

52 on purpose. It names a file the payload reads off the *node* and hands to a MongoDB 

53 driver as a URI; making it settable over the API would turn "change this app's 

54 configuration" into "read a chosen file on every database host" — every other 

55 field here only changes how PMM Extensions itself behaves, not what a probe reads off a 

56 monitored machine's filesystem. It is a deployment fact, and it belongs with the 

57 deployment. 

58 

59 :cvar SETTINGS_PREFIXES: Places this section under ``EXTENSIONS.OM_INVENTORY``. 

60 :param ENABLED: Whether the sweep may run at all, scheduled *or* manually 

61 triggered, independent of ``SCHEDULE``. Mirrors PMM's OpenManager on/off 

62 switch: pmm-managed flips this (not ``SCHEDULE``) when an operator toggles 

63 OpenManager, so the configured cadence survives being turned off and back on 

64 rather than being overwritten each time. Defaults to ``False``, matching 

65 PMM's own default for that switch, so a fresh deployment's estate does not 

66 start sweeping until OpenManager is actually turned on somewhere. 

67 :param SCHEDULE: How often the probe sweeps the estate, while ``ENABLED``. ``None`` 

68 unregisters the periodic job regardless of ``ENABLED``, leaving the trigger 

69 endpoint as the only way facts are refreshed. 

70 :param PROBE_DATABASE: Whether the payload connects to mongod and runs database 

71 commands. ``False`` collects process and OS facts only, which needs no credentials 

72 — and still yields ``installed_version``, the field this app exists for. 

73 :param CREDENTIALS_PATH: Node-side file holding the MongoDB URI to take credentials 

74 from. ``None`` falls back to ``~/.mongodb_uri``, the same file the PBM payloads 

75 read. 

76 :param REPO_URL: The file each host fetches to prove it can reach Percona's 

77 repository. Configurable because an air-gapped estate mirrors it somewhere 

78 else, and checking the public one there would report every host as broken. 

79 Restricted to HTTP/HTTPS: the payload hands it straight to 

80 ``urllib.request``, which would otherwise also accept ``file:`` or ``ftp:``. 

81 :param REPO_TIMEOUT: How long that fetch may take, seconds. Short on purpose: a 

82 repository slow enough to exceed it is not usable by a package manager 

83 either, so waiting longer only delays the same answer. 

84 :param CONNECT_TIMEOUT: Per-target connect and server-selection timeout, seconds. 

85 :param TASK_TIMEOUT: How long to wait for one dispatched probe task to reach a 

86 terminal status before giving up on it, seconds. 

87 :param POLL_INTERVAL: Delay between task-status polls, seconds. 

88 :param MAX_CONCURRENT_PROBES: Ceiling on probe tasks in flight at once. Every 

89 dispatch is a Nomad job, and a real estate has far more hosts than this 

90 workspace's sandbox. Bounded well under the Tasks API's own database pool 

91 (``POOL_SIZE`` + ``MAX_OVERFLOW``, 5 by default) on purpose: each 

92 host in flight polls that same API on its own ``POLL_INTERVAL`` clock for 

93 the whole sweep, not just once at dispatch, so this is a sustained call 

94 volume against that pool, not a one-time burst. A value at or above the 

95 pool's own size guarantees queueing on every poll cycle regardless of any 

96 other traffic sharing that pool — dispatch.py's bounded capacity retry 

97 absorbs a brief race, not a fan-out that structurally outnumbers the 

98 connections available to serve it. 

99 :param RUN_RETENTION: How many runs to keep. Each carries a per-host receipt, so 

100 this bounds the table rather than an operator having to. 

101 :param STALE_RUN_AFTER: How long a run may stay ``running`` before the trigger 

102 endpoint concludes its worker is gone. Must comfortably exceed the slowest 

103 legitimate sweep, which dispatches ``MAX_CONCURRENT_PROBES`` hosts at a time 

104 and can take up to ``TASK_TIMEOUT`` per batch: for an estate of ``N`` hosts 

105 that is roughly ``ceil(N / MAX_CONCURRENT_PROBES) * TASK_TIMEOUT``. The 

106 default covers estates up to a few hundred hosts at the defaults above; 

107 raising ``MAX_CONCURRENT_PROBES`` or targeting a much larger estate should 

108 raise this too, or the trigger endpoint reaps a sweep that is still running 

109 and reopens the single-flight race this check exists to close. 

110 """
