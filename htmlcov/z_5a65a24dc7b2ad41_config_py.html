348

358 :return: The input unchanged when no ``pmm`` key is present. 

359 :raises ValueError: When the input carries a ``pmm`` key (any case). 

360 """

362 isinstance(k, str) and k.lower() == "pmm" for k in data 

363 ): 

364 raise ValueError( 

365 "Per-syncer 'pmm:' override is no longer honored (removed in SEP-1477); " 

366 "PMM synchronizers read the top-level 'PMM' section. Remove the stale " 

367 "'pmm' key from EXTENSIONS.SYNCERS / EXTENSIONS.SYNCER_EXTRA_KWARGS." 

368 ) 

369 return data

547def materialize_delivery_plan_inputs(ctx: MaterializerContext) -> Any: 

548 """Bind submitted delivery-plan inputs against the baked plan skeleton. 

549 

550 ``DeliveryPlan``'s cross-reference validator only checks that every cited 

551 secret name is declared, never the converse, so an extra name would persist 

552 in the stored row and come back to whoever submitted it as drift. 

553 

554 The name check applies to a payload submitted now 

555 (:attr:`~app.core.settings_override.MaterializerPurpose.VALIDATE`) and not to 

556 a row stored earlier. A row written against a skeleton an image upgrade has 

557 since changed is a condition the operator has to be told about, and raising 

558 here would only drop the row from the snapshot, leaving 

559 :func:`~app.extensions.bundle_upload.resolver.resolve_delivery_plan` unable to tell 

560 drift from a deployment that never configured delivery. Shape coercion stays 

561 strict on both paths, so a malformed row is still dropped. 

562 

563 Reading the skeleton off ``extensions_settings`` is safe because 

564 ``DIAGNOSTICS_DELIVERY`` is ``not_overridable_field``, so it never comes from 

565 the snapshot being rebuilt. 

566 

567 :param ctx: The materialization context. 

568 :return: The validated inputs, or ``None`` when the override clears them. 

569 :raises ValidationError: When the payload does not match the field's shape. 

570 :raises ValueError: When a submitted payload's secret names are not exactly 

571 the ones the skeleton declares. 

572 """ 

573 inputs = coerce_field_value(ctx.field_info, ctx.raw) 

574 if inputs is None or ctx.purpose is MaterializerPurpose.SNAPSHOT: 

575 return inputs 

576 skeleton = extensions_settings.DIAGNOSTICS_DELIVERY 

577 declared = frozenset(skeleton.secrets) if skeleton is not None else frozenset() 

578 submitted = frozenset(inputs.secrets) 

579 if submitted != declared: 

580 problems: list[str] = [] 

581 if undeclared := sorted(submitted - declared): 

582 problems.append(f"undeclared secret names {', '.join(undeclared)}") 

583 if missing := sorted(declared - submitted): 

584 problems.append(f"missing secret names {', '.join(missing)}") 

585 raise ValueError( 

586 f"Delivery-plan inputs do not match the configured plan: " 

587 f"{'; '.join(problems)}." 

588 ) 

589 return inputs

851 @model_validator(mode="after") 

852 def add_syncer_extra_kwargs(self) -> Self: 

853 """Integrate extra keyword arguments into synchronizers. 

854 

855 Merge additional keyword arguments from ``SYNCER_EXTRA_KWARGS`` into each 

856 synchronizer in ``SYNCERS`` and update the list accordingly. Every override 

857 surface lands in this merge, so it is also where a constrained threshold is 

858 checked against the type its syncer field declares. Merging again with the 

859 same ``SYNCER_EXTRA_KWARGS`` leaves ``SYNCERS`` as it was. 

860 

861 :return: The updated ``ExtensionsSettings`` instance with modified ``SYNCERS``. 

862 :raises ValueError: When a merged threshold carries an unusable value. 

863 """ 

864 # ``model_validate`` runs an after-validator twice, and ``deep_dict_update`` 

865 # prepends for a list, so re-merging a merged value concatenates it with 

866 # itself. Each run re-derives from the pre-merge payloads instead, re-taking 

867 # them only when SYNCERS holds something this merge did not produce. 

868 current = [syncer.model_dump() for syncer in self.SYNCERS] 

869 if current != self._merged_syncers: 

870 self._pre_merge_syncers = current 

871 syncers = UniqueList() 

872 extra_kwargs = self.SYNCER_EXTRA_KWARGS.model_dump(exclude_none=True) 

873 for syncer_data in self._pre_merge_syncers: 

874 # deep_dict_update mutates nested dicts in place; keep the snapshot intact. 

875 merged = deepcopy(syncer_data) 

876 deep_dict_update(merged, extra_kwargs) 

877 _validate_constrained_syncer_extras(merged, extra_kwargs) 

878 syncers.append(SyncOptions.model_validate(merged)) 

879 self.SYNCERS = syncers 

880 self._merged_syncers = [syncer.model_dump() for syncer in syncers] 

881 return self

887def prefixed_cookie_path(path: str | None) -> str | None: 

888 """Return a cookie ``Path`` anchored under the configured URL prefix. 

889 

890 A browser matches ``Path`` against the URL it requests, which carries the 

891 prefix, so a root-anchored value would be withheld from every prefixed 

892 endpoint, and a cookie the browser never sends is indistinguishable from one 

893 that was never set. ``None`` is returned unchanged: with no ``Path`` 

894 attribute the browser derives one from the request URI, which already 

895 carries the prefix. 

896 

897 :param path: The configured cookie path, or ``None`` to leave the attribute 

898 unset. 

899 :return: The path to emit, prefixed when both a prefix and a path are 

900 configured. 

901 """ 

902 if path is None: 

903 return None 

904 return f"{extensions_settings.ROOT_PATH}{path}"
