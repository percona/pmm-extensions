16"""Encrypt and decrypt the credential-bearing leaves of a stored override value. 

17 

18Override rows persist through a JSON column, and 

19:func:`~app.core.settings_override.registry.unwrap_secrets_for_storage` strips 

20the :class:`~pydantic.SecretStr` wrapper before the value is written, so the 

21credential would otherwise reach the database in the clear. The walker here maps 

22a settings field's *annotation* onto the stored JSON positionally and transforms 

23the leaves that carry a credential. 

24 

25That annotation comes from one of two sources. The read and write paths pass the 

26live settings class, so they always track the current field set. A re-encryption 

27data migration passes a frozen replica model declaring the shapes that revision 

28was authored to cover, so its reach cannot drift with a later rename. Both are 

29plain :class:`~pydantic.BaseModel` subclasses as far as this module is 

30concerned, and nothing below distinguishes them. 

31 

32Two leaf kinds qualify, and they differ in how much of the leaf is rewritten. A 

33**Pydantic secret** leaf is the credential, so the whole value is transformed. A 

34**credential-bearing URL** leaf — recognized from the ``WrapSerializer`` marker 

35:data:`~app.core.utils.fields.CredentialHttpUrl` and its siblings carry, not 

36from any secret type — merely embeds one in its userinfo segment, so only that 

37password is transformed and the endpoint stays readable in a raw database dump. 

38 

39Which leaves carry a credential is decided **only** from the annotation, never 

40from the stored JSON's shape or content. A materializer-backed field stores the 

41client's raw payload rather than the coerced model, and is handled on the same 

42terms as a plain one because of that. The annotation is always resolved through 

43:func:`~app.core.settings_override.registry.annotated_type`, because Pydantic 

44hoists a non-``Optional`` field's ``Annotated`` metadata onto ``FieldInfo`` and 

45the URL marker lives in exactly that metadata. 

46 

47Where two candidate models at one JSON position declare a field of the same 

48name and only one types it as credential-bearing, that annotation wins, so the 

49value is encrypted rather than stored in the clear. No such collision exists in 

50``app/`` today. 

51 

52The three broad entry points cover both kinds, which the read and write paths 

53need. The two ``*_credential_url_leaves`` entry points cover only the URL kind, 

54so the data migrations that call them are exact inverses of each other and never 

55rewrite a secret an earlier revision already owns. 

56 

57Every leaf written here carries the versioned envelope marker 

58:func:`~app.core.encryption.mark_ciphertext` applies, so "is this already 

59encrypted?" is answered from the stored value's own format. The structural 

60:func:`~app.core.encryption.is_encrypted` check survives only as the fallback 

61for rows written before the envelope shipped: nothing re-marks those, because 

62deciding an unmarked row is ciphertext is exactly the guess the envelope exists 

63to replace. :func:`unmark_secret_leaves` strips the marker for a rollback, which 

64is why the envelope can be removed without the key. 

65"""

113def encrypt_secret_leaves( 

114 settings_cls: type[BaseModel], 

115 key: str, 

116 value: Any, 

117) -> Any: 

118 """Return ``value`` with every secret-typed leaf encrypted. 

119 

120 Encrypts unconditionally, which is what the write path needs: the values 

121 reaching it are freshly coerced from the request body, and the one that is 

122 reused rather than submitted (a secret restored because the client sent the 

123 redaction mask back) is read from the decrypted snapshot. Deciding 

124 structurally whether a leaf "looks encrypted" would misread a credential 

125 that happens to be base64 as ciphertext and store it in the clear. 

126

128 recognises what this stored from the value's own format rather than guessing 

129 it from the bytes. 

130 

131 Covers both leaf kinds: a Pydantic secret leaf is encrypted whole, and a 

132 credential-bearing URL has only its userinfo password encrypted. 

133 

134 :param settings_cls: The settings class, or a migration's frozen replica of 

135 one, owning ``key``. 

136 :param key: The override row's key, ``__``-delimited for a nested leaf. 

137 :param value: The JSON-storable value about to be persisted. 

138 :return: A value of the same shape with its credential leaves encrypted. 

139 """ 

140 return _rewrite_leaves(settings_cls, key, value, _encrypt_leaf, _ALL_LEAF_KINDS)

143def reencrypt_secret_leaves( 

144 settings_cls: type[BaseModel], 

145 key: str, 

146 value: Any, 

147) -> Any: 

148 """Return ``value`` with every not-yet-encrypted secret leaf encrypted. 

149 

150 The idempotent variant the re-encryption migrations need, where the column 

151 genuinely may already hold ciphertext. A leaf already holding ciphertext is 

152 left byte-identical, so a second run rewrites nothing and ciphertext written 

153 under a different ``ENCRYPTION_KEY`` is never re-encrypted, which would 

154 destroy the only copy of its plaintext. 

155 

156 The envelope marker decides first, so a leaf this module wrote is recognised 

157 from its own format. :func:`~app.core.encryption.is_encrypted` survives as 

158 the *fallback* for rows written before the envelope shipped, where nothing 

159 but the bytes is available to decide on. That fallback is structural, so a 

160 legacy plaintext secret that is itself a well-formed Fernet token is skipped 

161 and stays in the clear. Attempting a decrypt to tell the two apart is not an 

162 option: a failure there cannot separate that case from the foreign-key one, 

163 and guessing wrong on the second destroys data. Only the write path is free 

164 of the ambiguity, and it uses :func:`encrypt_secret_leaves`. 

165 

166 Covers both leaf kinds. For a credential-bearing URL the idempotence check 

167 runs on the *password*, not the leaf: neither discriminator accepts a whole 

168 ``https://user:<token>@host/`` string — it is not a Fernet token and carries 

169 no marker of its own — so testing the leaf would re-encrypt an 

170 already-encrypted password on every run and destroy the plaintext. 

171 

172 :param settings_cls: The settings class, or a migration's frozen replica of 

173 one, owning ``key``. 

174 :param key: The override row's key, ``__``-delimited for a nested leaf. 

175 :param value: The stored value being rewritten in place. 

176 :return: A value of the same shape with its plaintext credentials encrypted. 

177 """ 

178 return _rewrite_leaves(settings_cls, key, value, _reencrypt_leaf, _ALL_LEAF_KINDS)

254def unmark_secret_leaves( 

255 settings_cls: type[BaseModel], 

256 key: str, 

257 value: Any, 

258) -> Any: 

259 """Return ``value`` with the envelope marker stripped from every leaf. 

260 

261 The rollback transform, and the reason it can exist at all: stripping the 

262 marker is a string operation over the stored text, so it leaves a bare 

263 Fernet token a release predating the envelope reads correctly — without 

264 holding ``ENCRYPTION_KEY``, without a decrypt, and without the plaintext 

265 ever being written back to the column. 

266 

267 Covers both leaf kinds, because :func:`encrypt_secret_leaves` marks both. A 

268 leaf carrying no marker is returned byte-identical, so this is idempotent 

269 and a row written before the envelope is never touched. 

270 

271 There is deliberately no ``mark_secret_leaves`` counterpart. Marking an 

272 existing row requires deciding it is ciphertext, which for an unmarked row 

273 is exactly the structural guess the envelope exists to stop trusting, and 

274 marking a legacy collision plaintext would freeze that misclassification 

275 permanently. 

276 

277 :param settings_cls: The settings class owning ``key``. 

278 :param key: The override row's key, ``__``-delimited for a nested leaf. 

279 :param value: The stored value being rewritten in place. 

280 :return: A value of the same shape with its leaves unmarked. 

281 """ 

282 return _rewrite_leaves(settings_cls, key, value, _unmark_leaf, _ALL_LEAF_KINDS)

325def _reencrypt_leaf(leaf: str) -> str: 

326 """Return ``leaf`` encrypted and marked unless it already holds ciphertext. 

327 

328 The envelope answers first: :func:`~app.core.encryption.marked_ciphertext` 

329 accepts only a value carrying the marker over a well-formed payload, so a 

330 leaf this module wrote is always recognised and a legacy plaintext that 

331 merely starts with the marker is not. Anything it declines falls to the bare 

332 structural check, the discriminator for rows written before the envelope 

333 shipped — including a legacy plaintext that satisfies it by accident, an 

334 ambiguity this cannot resolve and does not make worse. 

335 

336 :param leaf: The stored leaf being rewritten. 

337 :return: The leaf unchanged, or marked ciphertext. 

338 """ 

339 if is_stored_ciphertext(leaf): 

340 return leaf 

341 return _encrypt_leaf(leaf)

344def _decrypt_leaf(leaf: str) -> str: 

345 """Return the plaintext behind ``leaf``, or ``leaf`` when it is not ciphertext. 

346 

347 A value carrying the marker over a *damaged* payload is returned as-is 

348 rather than raised on, and that is a deliberate choice with a cost worth 

349 naming: the marker is evidence the writer stored ciphertext there, so 

350 passing it through hands the caller an ``extensions.enc.v1.``-prefixed string as if 

351 it were the credential. Raising instead would drop the row with a warning, 

352 which :mod:`app.core.settings_override.cache` already handles. 

353 

354 Passing through is kept because it matches the unmarked path exactly — a 

355 corrupt bare token is returned untouched too — so no stored value changes 

356 behaviour on the day the envelope ships, which is the property the whole 

357 change is built around. Nothing in this module can produce the shape: it 

358 needs a value that was marked and then damaged in the column. 

359 

360 :param leaf: The stored leaf being read. 

361 :return: The plaintext, or the leaf unchanged. 

362 :raises DecryptionError: If the leaf is ciphertext the configured 

363 ``ENCRYPTION_KEY`` cannot decrypt. 

364 """ 

365 token = marked_ciphertext(leaf) 

366 if token is not None: 

367 return decrypt(token) 

368 return decrypt(leaf) if is_encrypted(leaf) else leaf

381def _annotation_for_key(settings_cls: type[BaseModel], key: str) -> Any: 

382 """Return the annotation of the field ``key`` overrides, or ``None``. 

383 

384 Resolved through :func:`~app.core.settings_override.registry.annotated_type` 

385 rather than read off ``.annotation``: Pydantic hoists a non-``Optional`` 

386 field's ``Annotated`` metadata onto ``FieldInfo``, and the credential-URL 

387 marker lives in exactly that metadata. 

388 

389 :param settings_cls: The settings class, or a migration's frozen replica of 

390 one, owning ``key``. 

391 :param key: The override row's key, ``__``-delimited for a nested leaf. 

392 :return: The leaf annotation, or ``None`` when ``key`` resolves to no field.

398 return None if field_info is None else annotated_type(field_info)

401def _positional_args(annotation: Any) -> list[Any]: 

402 """Return the types a value at this JSON position may take, in declaration order. 

403 

404 Strips :data:`~typing.Annotated` wrappers, flattens unions and drops 

405 ``NoneType``. Unlike the recursive walk behind 

406 :func:`~app.core.settings_override.registry.annotation_contains_secret` 

407 this does **not** descend through a model into its fields: a value at one 

408 position cannot be an arbitrary attribute of a model reachable from it. 

409 

410 Order is part of the contract rather than an accident of the traversal: 

411 :func:`_first_credential_bearing` resolves a contested position by taking 

412 the first candidate that reaches a transformable leaf, so a union's members 

413 have to arrive in the order the annotation declares them. Pushing them 

414 reversed onto a LIFO stack is what preserves that. 

415 

416 :param annotation: The annotation to flatten. 

417 :return: The candidate types for this position, in declaration order. 

418 """ 

419 flattened: list[Any] = [] 

420 stack = [annotation] 

421 while stack: 

422 current = stack.pop() 

423 if current is type(None): 

424 continue 

425 if hasattr(current, "__metadata__"): 

426 stack.append(typing.get_args(current)[0]) 

427 continue 

428 if typing.get_origin(current) in {Union, UnionType}: 

429 stack.extend(reversed(typing.get_args(current))) 

430 continue 

431 flattened.append(current) 

432 return flattened

446class _LeafKind(Enum): 

447 """Name the leaf kinds the walker knows how to transform. 

448 

449 Both kinds carry a credential; they differ in how much of the leaf is one. 

450 A ``PYDANTIC_SECRET`` leaf — one reaching :class:`~pydantic.SecretStr` or 

451 :class:`~pydantic.SecretBytes` — *is* the credential, so the whole value is 

452 transformed. A ``CREDENTIAL_URL`` leaf merely embeds one in its userinfo 

453 segment, so only that password is, leaving the endpoint readable in a raw 

454 database dump. 

455 """ 

456 

457 PYDANTIC_SECRET = 1 

458 CREDENTIAL_URL = 2 

459 

460 

461#: Every leaf kind, which the read and write paths must both cover. 

462_ALL_LEAF_KINDS = frozenset(_LeafKind) 

463 

464#: The credential-URL leaf alone, so a migration scoped to it is an exact 

465#: inverse of itself and never rewrites a secret an earlier revision owns. 

466_CREDENTIAL_URL_ONLY = frozenset({_LeafKind.CREDENTIAL_URL})

471 

472 :param annotation: The annotation to inspect. 

473 :param kinds: The leaf kinds this walk transforms. 

474 :return: ``True`` when the walk can still find something to rewrite below. 

475 """ 

476 return ( 

477 _LeafKind.PYDANTIC_SECRET in kinds and annotation_contains_secret(annotation) 

478 ) or ( 

479 _LeafKind.CREDENTIAL_URL in kinds 

480 and annotation_contains_credential_url(annotation)

484def _first_credential_bearing( 

485 candidates: list[Any], kinds: frozenset[_LeafKind] 

486) -> Any: 

487 """Return the first candidate reaching a selected kind, or ``None`` when none does. 

488 

489 Two annotations can compete for one JSON position: a union of container 

490 types, or the same field name declared by two candidate models. Preferring 

491 the credential-bearing one keeps the walker conservative, so a value that 

492 may be a credential is encrypted rather than stored in the clear. 

493 

494 Returning ``None`` rather than an arbitrary survivor is what makes the 

495 container branches fall through to the model branch: ``dict[str, str] | 

496 Inner`` would otherwise resolve to the mapping's plain ``str`` values and 

497 never look inside ``Inner`` for its secret. 

498 

499 ``kinds`` is honoured here as well as at the leaf, so a narrowed walk never 

500 resolves a contested position to a candidate it would then decline to 

501 transform. 

502 

503 :param candidates: The competing annotations, in declaration order. 

504 :param kinds: The leaf kinds this walk transforms. 

505 :return: The first credential-bearing annotation, or ``None``. 

506 """ 

507 return next( 

508 (candidate for candidate in candidates if _kinds_reachable(candidate, kinds)), 

509 None, 

510 )

612) -> Any:

630 """

634 for model in models

644def _credential_url_text(value: Any) -> str | None: 

645 """Return the URL text a credential-URL leaf holds, or ``None``. 

646 

647 The write path hands the walker the *validated* value, which for a 

648 :data:`~app.core.utils.fields.CredentialHttpUrl` field is a 

649 :class:`~pydantic.HttpUrl` rather than a string; the migration and read 

650 paths hand it the JSON column's text. Both reach this leaf, so the branch 

651 normalizes pydantic's single-host URL objects (an :class:`~pydantic.AnyUrl` 

652 subclass such as :class:`~pydantic.HttpUrl`, or a bare 

653 :class:`pydantic_core.Url`) rather than testing for 

654 ``str`` — a ``str``-only guard would 

655 silently skip every field typed ``CredentialHttpUrl`` on the one path that 

656 writes them. 

657 

658 :param value: The stored value at a credential-URL position. 

659 :return: The URL as text, or ``None`` when the leaf is neither. 

660 """ 

661 if isinstance(value, str | AnyUrl | Url): 

662 return str(value) 

663 return None

666def _transform_credential_url( 

667 value: Any, transform: Callable[[str], str], *, context: str 

668) -> Any: 

669 """Return ``value`` with ``transform`` applied to its embedded password. 

670 

671 A leaf that is neither text nor a URL object, or whose password segment is 

672 absent or unparseable, is returned unchanged: the walker never partially 

673 rewrites a URL it could not take apart. 

674 

675 Leaving an unparseable leaf alone is the right posture *here* and not 

676 generally. A stored value that cannot be parsed carries no password this 

677 could have encrypted, and refusing the whole row would abort a migration 

678 over one malformed endpoint. A caller whose job is to *mask* needs the 

679 opposite — which is why :func:`~app.core.utils.fields.credential_url_password` 

680 raises and each caller decides, rather than answering ``None`` for both. 

681 

682 Only that skip is logged. An endpoint carrying no credential is the ordinary 

683 shape, and this runs per row on every snapshot refresh, so announcing it 

684 would be steady-state output with nothing to act on, while a URL that cannot 

685 be parsed is an anomaly worth reading. 

686 

687 :param value: The stored value at a credential-URL position. 

688 :param transform: The password transformation to apply. 

689 :param context: The ``<class>.<key>`` this leaf belongs to, for the log line. 

690 :return: The rewritten value, or ``value`` when there is nothing to rewrite. 

691 """ 

692 text = _credential_url_text(value) 

693 if text is None: 

694 return value 

695 try: 

696 password = credential_url_password(text) 

697 except ValueError: 

698 logger.debug( 

699 "Left the credential-URL leaf of %s unchanged: it could not be parsed.", 

700 context, 

701 ) 

702 return value 

703 if password is None: 

704 return value 

705 return map_credential_url_password(text, transform)
