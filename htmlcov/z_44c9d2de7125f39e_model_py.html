37class AppFormModel(ConditionalRulesModel): 

38 """Serve as the single field declaration for a model-first plugin create form. 

39 

40 A subclass declares each form field once, as a Pydantic field whose 

41 ``Annotated[...]`` carries the DSL markers (``Ui`` plus optional ``Ref`` / 

42 ``Choices`` / ``Requires`` / ``Forbidden``). That one declaration drives both 

43 runtime validation and schema export: at class definition the conditional 

44 rules (field gates plus the model's ``__form_rules__``) are extracted into the 

45 inherited :attr:`~app.extensions.apps.framework.rules.ConditionalRulesModel.\ 

46__conditional_rules_plan__` so the inherited validator enforces them, while 

47 :func:`~app.extensions.apps.framework.form_dsl.derivation.derive_form_sections` 

48 derives the wire schema from the same fields. 

49 

50 :param alert_on_fail: Whether to alert on task failure and auto-resolve on a 

51 later success. Excluded from the derived schema — the framework renders it 

52 from the ``alert_on_fail`` capability — yet validated in the JSON body so 

53 every model-first form accepts it. Defaults to ``False``. 

54 :cvar __form_rules__: Section-scoped and plugin-scoped conditional rules that 

55 cannot attach to a single field (field-level gates live on the fields via 

56 ``Requires`` / ``Forbidden``). Defaults to an empty :class:`FormRules`. 

57 """

79class TaskFormModel(AppFormModel): 

80 """Provide the Task-section identity fields every task-based plugin form shares. 

81 

82 Task plugins all open their form with the same two fields — the task's name 

83 and the executor host it runs on — declared with identical DSL markers. This 

84 base centralises that single declaration the same way :class:`AppFormModel` 

85 centralises ``alert_on_fail``, so a task plugin's create model inherits 

86 ``task_name`` / ``hostname`` and declares only its plugin-specific fields. 

87 

88 Unlike ``alert_on_fail`` (a hidden, defaulted capability control), these are 

89 required, schema-visible fields, so a subclass's form layout must include a 

90 ``Task`` section. A non-task form model that needs no Task section should 

91 subclass :class:`AppFormModel` directly instead. 

92 

93 :param task_name: The human-readable task name; required and non-empty. 

94 :param hostname: The executor host the task runs on; required and non-empty. 

95 The default ``HostRef(target_service="service_id")`` ties the 

96 co-location warning to a service field named ``service_id``; subclasses 

97 that name their service field differently must override with an explicit 

98 ``HostRef(target_service=...)``. 

99 """

102 hostname: Annotated[ 

103 NonEmptyStr, 

104 HostRef(target_service="service_id"),
