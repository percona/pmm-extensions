22Perform two PostgreSQL-only operations during the upgrade downtime window: 

23 

241. ``ALTER TABLE taskhistory ALTER COLUMN execution_request TYPE jsonb USING 

25 execution_request::jsonb`` rewrites every row under ``ACCESS EXCLUSIVE``. 

26 The cost scales with ``taskhistory`` row count (approximately one minute 

27 per two million rows on typical production hardware); size the upgrade 

28 window accordingly. The operation is safe under SEP's standard upgrade 

29 downtime because no concurrent writers compete for the lock. 

302. ``CREATE INDEX ix_taskhistory_execution_request_meta ON taskhistory USING 

31 GIN ((execution_request->'meta') jsonb_path_ops)`` builds a GIN expression 

32 index used by the ``@>`` containment clauses emitted by 

33 ``_raise_if_identical_task_conflict``. ``jsonb_path_ops`` is the smallest 

34 and fastest operator class for ``@>`` queries; it does not support the 

35 ``?`` / ``?&`` / ``?|`` key-existence operators, so a future ticket that 

36 needs those operators against ``execution_request->'meta'`` must rebuild 

37 the index with the default ``jsonb_ops``. Plain ``CREATE INDEX`` (not 

38 ``CONCURRENTLY``) is correct here because the downtime window has no 

39 traffic, and a synchronous build rolls back atomically on failure with no 

40 ``INVALID`` index state to clean up. 

41 

42SQLite and MySQL: no-op. SQLite has no distinct ``jsonb`` type and its 

43``json_extract`` path is unchanged. MySQL stays on plain JSON for the same 

44reason SEP-818 skipped MySQL indexing (fixed-width ``CAST`` truncation risk 

45in functional indexes).
