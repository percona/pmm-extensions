22``service.external_id`` is NOT NULL as of e4b8c2f7a915, so every row now carries 

23an external identity. ``ix_service_port_node_id`` constrained ``(port, node_id, 

24retirement_key)`` for every row regardless of identity, which rejected the 

25legitimate case of several databases behind one PostgreSQL or MySQL server 

26sharing that server's port and being registered as separate services. Dropping 

27it outright is the honest version of narrowing it to a NULL-able discriminator: 

28that approach relied on an externally identified row carrying a NULL guard 

29(unique indexes treat NULLs as distinct), and since every row is externally 

30identified now, the guard would be NULL for all of them and the constraint 

31would already be inert for everyone. 

32

34see its own docstring for why. It also has to leave the index in place for 

35c7d1e94ab3f2's downgrade, several steps further back in the chain: that 

36revision unconditionally drops and recreates ``ix_service_port_node_id`` as 

37part of restoring the pre-retirement-key indexes, so a downgrade chain running 

38through both revisions needs the index to exist by the time it gets there.
