59class LinkageMethodEnum(StrEnum): 

60 """Enumerate how an external-identity binding came to be recorded. 

61 

62 Every member names an operator action: nothing here records a binding the 

63 syncer made on its own, because ordinary sync creation writes no alias row. 

64 

65 Values are spelled out rather than derived with ``auto()``. The column 

66 persists the member *name*, but the API serializes the *value*, so under 

67 ``auto()`` the two move in opposite ways when a member is renamed: the 

68 stored form follows the rename while the published one silently changes 

69 with it. Pinning the value holds the wire contract — this enum reaches the 

70 generated API client — and leaves a rename a database concern alone. 

71 """ 

72 

73 OPERATOR_CONFIRMATION = "operator_confirmation" 

74 OPERATOR_UNLINK = "operator_unlink" 

75

77class IdentityLinkDecisionEnum(StrEnum): 

78 """Enumerate the decisions an operator may record against a candidate pairing. 

79 

80 :cvar CONFIRMED: The pairing names one machine, and the link stands. 

81 :cvar REJECTED: The pairing names two machines, so stop suggesting it. 

82 :cvar UNLINKED: A standing confirmation was reversed. 

83 

84 Values are spelled out for the reason given on 

85 :class:`LinkageMethodEnum`, and it binds harder here: this enum is also a 

86 *request* body field, so a rename would reject the payloads callers were 

87 already sending. 

88 """ 

89 

90 CONFIRMED = "confirmed" 

91 REJECTED = "rejected" 

92 UNLINKED = "unlinked"
