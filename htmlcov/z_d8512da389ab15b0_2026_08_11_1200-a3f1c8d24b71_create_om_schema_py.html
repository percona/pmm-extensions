16"""create the om schema and its tables 

17 

18Revision ID: a3f1c8d24b71 

19Revises: 

20Create Date: 2026-08-11 12:00:00.000000 

21 

22The whole OM schema in one revision: ``om.om_host`` and ``om.om_service`` for what the 

23estate *is*, ``om.om_inventory_run`` for what one sweep *did*. Table names carry an 

24``om_`` prefix on top of the schema that already qualifies them, because the schema 

25alone does not: the real-PostgreSQL test lane translates every declared schema 

26token into the same per-worker schema, which collapsed bare 

27``service`` onto SEP inventory's own ``service`` (``schema=None``) the first time 

28this app's tables were exercised against a real, non-SQLite database — see 

29``app/sep/apps/om_inventory/models.py``'s module comment for the full account. 

30 

31Rewritten in place rather than extended by follow-up revisions - the host counters on 

32``om_inventory_run`` and the ``SKIPPED`` run status were each a revision of their own 

33while this branch was being written, and both are folded in here - because none of this 

34has shipped — there is no deployment whose data a move migration would preserve. The 

35cost is local: a machine that ran an earlier version of this revision has to drop 

36what it created and delete the ``a3f1c8d24b71`` row from ``alembic_version_sep`` by 

37hand, since the migration that would have moved it deliberately does not exist. Once 

38OM ships, this file freezes and changes become new revisions. 

39 

40The schema is named symbolically throughout — ``schema="om_schema"``, translated by 

41the connection (``app/sep/migrations/env.py``) — with the single exception of 

42``CREATE SCHEMA``, which is raw DDL and therefore untranslated. That statement asks 

43:func:`app.sep.apps.shared.om.config.om_schema` for the real name and does nothing 

44when the bind has no schemas. 

45 

46Alembic's comparison sees these tables at their translated schema — 

47``app/sep/migrations/env.py`` hands it a translated copy of the metadata — so an 

48in-sync ``alembic check`` is clean. ``--autogenerate`` renders the *resolved* 

49schema instead (``None`` on SQLite, the real name on PostgreSQL), so a generated 

50OM script still has to be edited to name ``OM_SCHEMA_SYMBOL`` before it is 

51committed. 

52"""

73 """Build an ``observed`` document column.

76 stores a Python ``None`` as the JSON scalar ``null``, which would make "never 

77 probed" and "probed, found nothing" the same value in the column.

79 The default is parenthesised rather than bare. On both dialects SEP runs the
