45#: Fraction of the prefork pool's child-liveness deadline the inline seed may 

46#: consume. Strictly below 1.0: ``process_initializer`` does more than the 

47#: seed, and the child must still send ``WORKER_UP`` inside the same window. 

48SEED_TIMEOUT_FRACTION = 0.5

51class WorkerRefresher: 

52 """Own one prefork child's settings-override boundary refresher. 

53 

54 Hold the lifecycle boilerplate every worker-side refresher needs — the 

55 enabled gate, the idempotent already-armed early-return, the initial 

56 inline seed, and disarm on shutdown — so each service module only 

57 supplies its own event loop, session maker and proxy set. After 

58 :meth:`start`, refreshes are pulled from ``task_prerun`` via 

59 :meth:`maybe_refresh` rather than driven by a background 

60 ``asyncio.sleep`` loop: a prefork child's loop only runs inside 

61 ``run_until_complete`` windows, so a timer-based cycle could starve. 

62 

63 Every dependency is a zero-argument callable resolved at :meth:`start` 

64 time, never a value captured at construction: the instance is a 

65 module-level singleton built at import, while the event loop is recreated 

66 per prefork child and the session maker is rebound in tests. The 

67 last-refresh timestamp is likewise per-child after the fork. ``now`` is 

68 the same shape so tests can advance the due-check without writing 

69 ``_last_refresh``. 

70 

71 ``interval``, ``enabled`` and ``proc_alive_timeout`` are :meth:`start` 

72 parameters rather than reads of ``app.core.config.settings`` because the 

73 override substrate must not import that module at runtime — ``Settings`` 

74 is itself built from :mod:`app.core.settings_override.proxy`. 

75 

76 :param loop_getter: Returns the event loop that drives the seed and 

77 boundary refreshes. 

78 :param session_maker_factory: Returns the service-scoped 

79 ``async_sessionmaker`` the refresh cycle reads override rows through. 

80 :param proxies_factory: Composes the proxy registry to refresh, invoked 

81 once per effective :meth:`start`. 

82 :param now: Returns the monotonic clock used for the due-check and 

83 last-refresh stamp. Defaults to :func:`time.monotonic`. 

84 """

104 def start( 

105 self, 

106 interval: timedelta | None = None, 

107 *, 

108 enabled: bool | None = None, 

109 callbacks: CallbackRegistry | None = None, 

110 proc_alive_timeout: float | None = None, 

111 ) -> None: 

112 """Seed this child's overrides and arm boundary refresh, unless disabled. 

113 

114 The initial refresh awaits inline so the snapshot is seeded before this 

115 method returns. No periodic ``asyncio.Task`` is created: subsequent 

116 refreshes are pulled from :meth:`maybe_refresh` at task boundaries. 

117 

118 When ``proc_alive_timeout`` is set, the inline seed is bounded to 

119 :data:`SEED_TIMEOUT_FRACTION` of that deadline via 

120 :func:`~app.core.settings_override.lifecycle.bounded_seed` so a hanging 

121 database cannot push the child past the prefork pool's liveness window. 

122 On seed-budget expiry the child is still armed — the next due 

123 ``task_prerun`` will refresh once any cancelled seed has finished 

124 unwinding — and may retain a possibly incomplete seed (proxies 

125 published before the hang keep DB overrides; others stay on their prior 

126 snapshots) until then. A cancelled seed that is still unwinding is 

127 retained on ``_pending_refresh`` so :meth:`maybe_refresh` does not open 

128 another session while the stuck cleanup holds a pool connection. 

129 

130 :param interval: Minimum delay between boundary refreshes. ``None``, 

131 the default, reads 

132 ``Settings.SETTINGS_OVERRIDE.REFRESH_INTERVAL``. 

133 :param enabled: Whether to arm a refresher at all. When ``False`` 

134 nothing is resolved (neither the proxy registry nor the session 

135 maker) and the child stays disarmed. ``None``, the default, reads 

136 ``Settings.SETTINGS_OVERRIDE.REFRESHER_ENABLED``. 

137 :param callbacks: Optional rebind callbacks fired by a boundary 

138 :func:`~app.core.settings_override.lifecycle.refresh_all` when a 

139 watched override changes value. The inline seed fires only those 

140 marked with :func:`~app.core.settings_override.lifecycle.fire_on_boot`, 

141 for keys it published an override for. 

142 :param proc_alive_timeout: The prefork pool's child-liveness deadline 

143 in seconds. ``None`` (the default) leaves the inline seed 

144 unbounded. 

145 :raises Exception: Re-raises whatever ``proxies_factory()`` raises — 

146 it is evaluated before the refresh starts — and whatever an 

147 unbounded seed propagates, in practice limited to 

148 ``session_maker_factory()`` failures. Per-proxy refresh failures 

149 are caught and logged inside ``refresh_all``. A bounded-seed 

150 expiry is caught inside :func:`~app.core.settings_override.lifecycle.bounded_seed` 

151 and does not propagate; the child is still armed. 

152 """ 

153 interval, enabled = resolve_refresher_options(interval, enabled=enabled) 

154 if not enabled: 

155 return 

156 if self._armed: 

157 return 

158 proxies = self._proxies_factory() 

159 seed_timeout = ( 

160 None 

161 if proc_alive_timeout is None 

162 else proc_alive_timeout * SEED_TIMEOUT_FRACTION 

163 ) 

164 seeded, pending = self._loop_getter().run_until_complete( 

165 bounded_seed( 

166 self._session_maker_factory, 

167 proxies, 

168 seed_timeout, 

169 callbacks=callbacks, 

170 ) 

171 ) 

172 now = self._now() 

173 self._last_refresh = now if seeded else now - interval.total_seconds() 

174 self._pending_refresh = ( 

175 pending if pending is not None and not pending.done() else None 

176 ) 

177 self._interval_seconds = interval.total_seconds() 

178 self._proxies = proxies 

179 self._callbacks = callbacks 

180 self._armed = True

182 def maybe_refresh(self) -> None: 

183 """Refresh overrides when armed and the interval has elapsed. 

184 

185 Intended for ``task_prerun`` receivers. The due-check is a monotonic 

186 comparison with no I/O: tasks arriving inside the interval no-op. 

187 When a prior bounded refresh (seed or boundary) was cancelled and is 

188 still unwinding, this method also no-ops without awaiting that task — 

189 so a stuck ``AsyncSession.__aexit__`` cannot pile up further pool 

190 checkouts at later boundaries. 

191 When due, ``refresh_all`` runs to completion inside a single 

192 ``run_until_complete`` window, bounded by the refresh interval itself 

193 via :func:`~app.core.settings_override.lifecycle.bounded_refresh` 

194 (``asyncio.wait``, cancel without awaiting unwind — not 

195 ``wait_for``, which would still hang on a stuck 

196 ``AsyncSession.__aexit__``). Budget expiry logs once at WARNING and 

197 retains the cancelled task handle; exceptions raised from the 

198 ``run_until_complete`` call are logged and swallowed. A failure that 

199 surfaces only while a cancelled refresh is still unwinding is logged 

200 by the drain callback when that task finishes, not by this method. 

201 Neither case fails or aborts the task that triggered the refresh. 

202 Because proxies publish sequentially, a timed-out or failed cycle may 

203 leave a split registry (earlier proxies refreshed, later ones on their 

204 prior snapshots) rather than rolling everything back. 

205 The interval stamp advances on every attempted due refresh so a 

206 failing cycle cannot hammer the database on every subsequent 

207 dispatch. 

208 """ 

209 if not self._armed or self._proxies is None: 

210 return 

211 if self._pending_refresh is not None: 

212 if not self._pending_refresh.done(): 212 ↛ 214line 212 didn't jump to line 214 because the condition on line 212 was always true

213 return 

214 self._pending_refresh = None 

215 now = self._now() 

216 if now - self._last_refresh < self._interval_seconds: 

217 return 

218 try: 

219 completed, pending = self._loop_getter().run_until_complete( 

220 bounded_refresh( 

221 self._session_maker_factory, 

222 self._proxies, 

223 self._interval_seconds, 

224 self._callbacks, 

225 ) 

226 ) 

227 if not completed: 

228 self._pending_refresh = ( 

229 pending if pending is not None and not pending.done() else None 

230 ) 

231 logger.warning( 

232 "Settings-override boundary refresh exceeded its %.2fs budget; " 

233 "leaving a possibly incomplete refresh in place", 

234 self._interval_seconds, 

235 ) 

236 except Exception: 

237 logger.exception( 

238 "Settings-override boundary refresh failed; " 

239 "leaving a possibly incomplete refresh in place" 

240 ) 

241 finally: 

242 self._last_refresh = self._now()

244 def stop(self) -> None: 

245 """Disarm this child's refresher; a no-op when never started. 

246 

247 After disarm, :meth:`maybe_refresh` no-ops so a shut-down child 

248 performs no further boundary refresh. There is no periodic task to 

249 cancel. A cancelled refresh still unwinding is dropped from 

250 ``_pending_refresh`` without being awaited — the prefork child is 

251 exiting. 

252 """ 

253 self._armed = False 

254 self._proxies = None 

255 self._callbacks = None 

256 self._pending_refresh = None
