Snippet interpreters are no longer run through `env -S`: the configured interpreter command (`EXTENSIONS.SNIPPETS.INTERPRETERS`, including `INTERPRETERS_PREPEND` / `INTERPRETERS_APPEND` entries) is split on whitespace and its words are run as they are. A custom command that relied on `env -S` syntax — a leading `NAME=VALUE` assignment, an `env` option such as `-u NAME`, quoted words, backslash escapes or `${VAR}` expansion — now fails: its executions are reported Unlaunchable, or Failed when the first word contains a `/` without being an absolute path (for example `PATH=/opt/bin bash`). A plain program name or absolute path with optional arguments, with or without a `sudo` prefix, is unaffected, which covers the shipped defaults. The change applies once the tasks service starts on this release. To keep a custom environment, point the command at a wrapper script by absolute path.
