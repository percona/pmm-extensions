PBM Configuration app, served at `/api/apps/backup_mongo/config/` as a child of MongoDB Backups, giving PBM's cluster-wide configuration its own surface alongside Backups and Restores instead of riding along with backup creation. It covers the config file `pbm config --file` writes: storage and its tuning (chunking, retries, server-side encryption, per-node endpoints), point-in-time recovery, backup options, and PBM's `restore` section, which had no representation before. Expert settings sit behind a single "Show advanced options" control.

Storage offers S3-compatible, MinIO, Google Cloud Storage, Azure Blob Storage, OCI Object Storage and Filesystem backends, each with its own section that appears only when that backend is selected. Alibaba OSS is not offered: PBM accepts it, but its published key names do not match the shipped binary, and a field that looks settable but reaches nothing is worse than an absent one. Credentials remain absent by design for every backend — access keys, session tokens, GCS service-account keys and the SSE customer key have nowhere safe to live in SEP, so they stay the business of whoever has the `pbm` CLI, and an apply carries them through untouched. A backend therefore has to be given its credentials from the CLI once before OM can configure it.
