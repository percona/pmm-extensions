The ProxySQL status report no longer prints credentials from its admin config file. The value of any setting whose name contains PASS, PW, SECRET, TOKEN, KEY, AUTH or CRED, or whose value holds a credential assignment such as `--password=...` or a URL or DSN with a password (`user:pass@host`), shows as `[REDACTED]`, including commented-out settings; an empty value still shows, without its trailing comment. A line that is not a plain `KEY=value` assignment, a line continuing a quoted value from the line above, and a comment that names a credential are replaced by `# [REDACTED: line not shown]`, since they could hold a secret the masking cannot find; after a line that leaves a command substitution, expansion, array, line continuation or here-document open, every remaining line is replaced the same way. Other settings, blank lines and other comments still show as written. The fix reaches an installation on the first snippet sync after upgrade: the updated built-in script is re-approved automatically only when built-in auto-approval is on and an administrator has not revoked its approval; otherwise an administrator must approve it before it runs.
