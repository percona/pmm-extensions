PMM Extensions now refuses to start when TASKS.INVENTORY_SYNC_SYNCER or an entry of TASKS.INVENTORY_SYNC_SCHEDULES names a syncer that matches no EXTENSIONS.SYNCERS entry, instead of seeding a schedule that fails on every firing; the error names the offending setting and value and lists the configured syncers. Names are compared in their full "module.ClassName" form, so a short EXTENSIONS.SYNCERS spelling such as PMMSyncer still matches app.extensions.sync.syncers.pmm.PMMSyncer. A pinned or scheduled syncer must therefore also be listed in EXTENSIONS.SYNCERS; the shipped profiles already list theirs. The check runs in the combined app before it seeds the schedule and in the standalone extensions app; the standalone tasks service still checks the name's format only, so in a split deployment it seeds an unmatched name while the extensions app refuses to start. The standalone extensions app now also imports its configured syncers at startup when a syncer is pinned or scheduled, so an unimportable EXTENSIONS.SYNCERS entry fails the boot rather than the first sync request.
