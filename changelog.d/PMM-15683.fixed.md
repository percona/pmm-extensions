A setting written one field at a time (a `PARENT__leaf` override) is now validated as the whole setting it produces. The settings API refuses with 422 a PATCH or DELETE that would leave that setting invalid, and applies two changes to one such setting one after the other, so the second is judged against the first: if the first takes longer than 5 seconds, the second answers 503 and changes nothing. Stored field overrides that together fail the setting's validation are ignored with a warning, so the setting keeps its whole-setting override if one is stored, and the deployment's value otherwise.
