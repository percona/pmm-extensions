Creating or renaming a schedule with a name longer than 255 characters now answers HTTP 422 naming the field, before anything is written. On PostgreSQL, which installations inside PMM use, it answered HTTP 500 (HTTP 502 through the extensions service). On SQLite such a name was stored, so a schedule that already has one is refused on its next update until it is renamed. A schedule created without a name for a task with a long name, or with a long crontab, now gets a generated name shortened to fit, where it also answered HTTP 500 on PostgreSQL before.
