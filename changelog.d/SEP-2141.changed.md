The 17 alert-linked MongoDB check snippets (connections, replication lag, WiredTiger cache and the rest) now accept MongoDB host, port, user, password and authentication database, so they return data on deployments with authentication enabled; the account needs the privileges the checks read with, and the clusterMonitor role covers the status commands. Every MongoDB shell snippet keeps the password off the command line of mongosh, mongo and mongostat, though the snippet's own command line still carries it: the shells read the credentials from stdin, and `mongodb_blocked_writes_check.sh` gives mongostat its password through a `--config` file descriptor instead of `-p`. User names and passwords containing line breaks or other control characters authenticate as given; a password with a control character can only belong to a SCRAM-SHA-1 credential, so mongostat is told to use that mechanism for one. A credentialed mongostat sample needs MongoDB Database Tools 100.3.0 or later, the first release with `--config`. A wrong user or password now stops the run before any output with `Error: MongoDB authentication failed for user '<user>' …` and exit status 1, instead of running unauthenticated, and a user without a password, or the reverse, is rejected. The ten snippets that already took credentials no longer print shell prompt lines in their output, and a section of theirs that fails, for example `sh.status()` against an endpoint that is not a mongos, now also prints its "Could not retrieve …" line after the error.
