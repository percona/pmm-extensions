The 17 alert-linked MongoDB check snippets (connections, replication lag, WiredTiger cache and the rest) now accept MongoDB host, port, user, password and authentication database, so they return data on deployments with authentication enabled; the account needs the privileges the checks read with, and the clusterMonitor role covers the status commands. Every MongoDB shell snippet now hands the password to mongosh, mongo and mongostat over stdin rather than on their command line, though the snippet's own command line still carries it. A wrong user or password now stops the run before any output with `Error: MongoDB authentication failed for user '<user>' …` and exit status 1, instead of running unauthenticated, and a user without a password, or the reverse, is rejected. The ten snippets that already took credentials no longer print shell prompt lines in their output.
