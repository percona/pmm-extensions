Fixed `om_bootstrap` rolling back a healthy replica set when the seed member lost its own election. `create_pmm_monitoring_user` ran on the seed and `createUser` is a write, so it required that member to be primary - but `rs.initiate` only proposes the config, and the election that follows is open to every member. When another member won, every attempt failed with `MongoServerError: not primary`, retries could not help because they all went to the same secondary, and the run tore down a set that was otherwise fine. The step now connects through a replica-set connection string naming every member, so the driver sends the write to whichever member is primary and waits up to 30s for one to be elected.
