With the Grafana auth provider, PMM Extensions' API accepts a Grafana service-account token (glsa_…) as Authorization: Bearer, authenticating as that service account with its own organization role, so automation can call PMM Extensions through PMM's /extensions/ prefix with the token it already uses for PMM. Tasks the service account runs show its login as the actor, and GET /api/users still lists human users only. PMM Extensions' own Grafana service account needs serviceaccounts:read (the organization Admin role the PMM side-car provisions has it); without it every valid service-account bearer is answered 502. The Casdoor provider is unchanged.
