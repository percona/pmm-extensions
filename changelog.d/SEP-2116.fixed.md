Setting an optional setting to `null` through an environment variable or the dotenv file now clears it instead of restoring its default, and wins over a value for the same setting in `settings.yaml`. The exact text `null` in any environment or dotenv value now means `None`, so a setting that does not accept `None` and is set to `null` this way now fails at startup with a validation error naming the setting, where it previously kept its default silently. A `null` in a secret file under `SECRETS_DIR` is still read as text.
