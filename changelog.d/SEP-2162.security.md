Snippet credential parameters (a name such as `password` or `token`, or `sensitive: true` in the front matter) are no longer shown back to people. The run form hides the value of a free-text string parameter as it is typed; a numeric parameter or one with a fixed list of choices is still shown in the form. Every task-history response, from the Tasks API and from the PMM Extensions routes that proxy it, now returns `execution_request.meta.args` with credential values replaced by `***`, for runs submitted after the upgrade. For any run that recorded arguments without a masked copy the same field is the fixed string `<withheld>`, non-credential arguments included: that is every run recorded before the upgrade, and every later run whose submitter sent none, such as a checksums run or a direct call to the Tasks API. The stored arguments are unchanged and the run still executes with the real values. With DEBUG logging on, the request PMM Extensions sends to start a run and the Tasks service's Nomad dispatch no longer log the run's arguments, configuration or payload, and PMM Extensions no longer logs the body of any Tasks API response, only its status, method and path. Task definitions an app stores (`task.data`) are not covered and are still logged when created or updated. Where PMM Extensions and the Tasks service are deployed separately, history keeps returning raw arguments until the Tasks service itself is upgraded.
