Task hook paths (`alert_detail_builder`, `run_result_recorder`) are now restricted to an allow-listed module namespace, closing a hole where any authenticated caller creating or updating a task could name an arbitrary importable callable for the tasks service to invoke. The allow-listed roots come from `TASKS.HOOK_MODULE_ALLOWLIST`, which defaults to `app.extensions.apps`; a deployment whose hook paths live outside that namespace must add its own root there before upgrading, or task creation will be rejected and existing tasks will stop resolving their hooks.
