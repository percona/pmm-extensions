A MySQL Restores XtraBackup restore with "Restore my.cnf" enabled no longer writes a config file wherever the backup's file names point. A restored config file may only land in `/etc/my.cnf`, `/usr/local/etc/my.cnf`, or under `/etc/mysql`, `/etc/my.cnf.d`, `/etc/percona-server.conf.d` or `/etc/percona-xtradb-cluster.conf.d`, checked after symlinks are resolved, and only when its directory already exists. A config file in the backup that is a symbolic link or has more than one hard link is refused. Any other entry fails the restore with an error naming the file and the reason, before any config file is written or directory created. A backup that carries only bare file names such as `my.cnf`, which is what this backup tool records, now fails with "no destination encoded" instead of an unclear file-not-found error. `backup-my.cnf`, `auto.cnf` and `mysqld-auto.cnf` stay in the data directory.
