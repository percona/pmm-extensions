Operations for MongoDB now refuses probe-timing settings that contradict each other: `POLL_INTERVAL` must not exceed `TASK_TIMEOUT`, and `STALE_RUN_AFTER` must exceed `TASK_TIMEOUT` in whole seconds, so a margin under one second is refused. A combination that v3.10.0 accepted under `EXTENSIONS.OM_INVENTORY` in `settings.yaml` or the `EXTENSIONS__OM_INVENTORY__*` environment variables now fails to load: the error names both fields and the relationship, is logged, and every read of the app's settings raises until the values are fixed, so check both relationships before upgrading. A PATCH or DELETE through `/api/apps/om_inventory/config` or the admin settings router that would break one answers 422 naming both fields. Stored overrides that together break one, for example after a later YAML or environment change, are ignored: those fields run on their YAML, environment or default values, and a warning naming them is logged on every settings refresh.
