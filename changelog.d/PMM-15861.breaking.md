A caller using `EXTENSIONS_INTERNAL_TOKEN` now gets 403 on any write that PMM Extensions' background work or PMM Server's bootstrap stepper and Operations switch do not make with it. This includes a PMM Server that does not yet call PMM Extensions with the user's own credential: deleting an Operations host or service or starting a bootstrap from PMM fails until PMM Server is upgraded to a release that does. Deciding an inventory identity link with the token is refused too.
