MySQL Restores: an XtraBackup restore with Restore my.cnf now writes each config file back to the path it was captured from, including paths that contain an underscore, instead of failing with "no destination encoded". Only files under the standard config locations (`/etc/my.cnf`, `/usr/local/etc/my.cnf`, `/etc/mysql`, `/etc/my.cnf.d` and the Percona Server and PXC `conf.d` directories) are restored; a backup that captured a config file anywhere else still refuses the whole step before writing anything. This applies to backups taken after upgrading; config files in older backups still have to be restored by hand.
