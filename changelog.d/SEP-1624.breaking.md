The snippets list endpoint drops the `order` query parameter; request descending order with a `-` prefix on `sort` (for example `sort=-created_at`). Its default ordering also changes from newest-first (`created_at` descending) to approved-first (`-approved_at`), so clients that relied on the previous default must now send `sort=-created_at` explicitly. An out-of-allowlist `sort` value still returns 422, but the body is now a flat `{"detail": "Invalid sort key: '<key>'"}` string rather than a field-keyed validation-error list. The inventory and tasks list endpoints' `sort` parameters gain the same allowlist enum, so a client passing a plain string there must narrow it too. API clients should regenerate `@pmm-extensions/api`.
