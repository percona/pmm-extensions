A failed Operations scan now reports the step that failed, its exit code and the node's own output instead of "no output", and carries a `last_error_code` that says what kind of failure it was. A scan refused because another is running now says which nodes a scan is already running on, instead of naming the run by its id. A running scan also records how many nodes have come back as it goes, with the node totals written as soon as they are known, so its progress can be shown instead of a spinner.
