`INVENTORY_SYNC_SCHEDULES` entries, such as the daily host-facts schedule, no longer wait for the pinned `INVENTORY_SYNC_SYNCER` default's first completed inventory sync before they run, so a default that never completes (an unreachable PMM, an `INVENTORY_SYNC_SYNCER` that matches no configured syncer, or a disabled default schedule) no longer stops them. Each entry runs on its own interval from bring-up, and the default's runs start it once more when it has not run since the default's first completed sync, including one made through the manual sync endpoint, so its next result covers the inventory that sync brought in.
