Renamed the side-car's contracts, stored names and user-facing text from SEP to PMM Extensions: settings use the `EXTENSIONS__` environment prefix and `EXTENSIONS` YAML section, deployment inputs and the build argument are `EXTENSIONS_*`, the side-car is served under `/extensions/` with its API at `/api/extensions/`, its Grafana service account is `pmm-extensions`, annotations and alerting objects are named PMM Extensions, the image is published as `percona/pmm-extensions` on Docker Hub, its state volume is `pmm-extensions-state` mounted at `/home/extensions/state`, the settings class is `ExtensionsSettings` (in `SETTINGS_OVERRIDE.ALLOWED_KEYS` entries and settings-export keys), and the upstream-failure response header is `X-Upstream-Error`. The old names are not accepted as aliases. Internal names follow: the Python package is `app.extensions` (distribution `pmm-extensions`), OpenAPI component schemas named after the product use the `Extensions` prefix, the task-log stream reports failures as the `extensions-error` event, the service principal is `extensions-service`, and the default Casdoor application is `extensions-app`. Existing databases, scheduled jobs and stored task paths are migrated forward on upgrade, and sessions issued before the upgrade are re-established once.
