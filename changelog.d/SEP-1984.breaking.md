A `DIAGNOSTICS_DELIVERY` plan carrying a key that its plan, step or value does not declare is now rejected when settings load, so PMM Extensions refuses to start and names the key and where it sits in the plan. Such a key used to be dropped in silence: an unquoted comma inside a YAML flow mapping, as in `{source: literal, value: number,short_description}`, truncated the value and the rest was discarded. A deployment that configured its own plan has to remove or correct any such key, and quote a value carrying a comma, before upgrading. Parameter names inside `headers`, `query`, `body` and `fields` are not affected, and the plan baked into the side-car image is unaffected.
