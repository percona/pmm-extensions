The ProxySQL status report reads the credentials in its --defaults-file as plain KEY=value settings and no longer runs the file as a shell script, so commands or substitutions written in it are never executed. A credential whose value would need shell expansion, or that spans lines, is ignored with a warning that names the setting but not its value, and falls back to its default even if an earlier line set it; a setting the file lacks also takes its default (host 127.0.0.1, port 6032, empty user and password) instead of a PROXYSQL_* environment variable. A directory given as --defaults-file is now refused like an unreadable file. The fix reaches an installation on the first snippet sync after upgrade: the updated built-in script is re-approved automatically only when built-in auto-approval is on and an administrator has not revoked its approval; otherwise an administrator must approve it before it runs.
