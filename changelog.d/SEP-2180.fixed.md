XtraBackup restores now apply the incremental chain: S3 (s3cmd and awscli) and GCS sources no longer restore only the full backup, local and SSH sources no longer fail with a TypeError when incrementals exist, and picking an incremental run as the source restores the full backup plus the chain up to that run. Every backup in the chain is checked before MySQL is stopped, and a chain that cannot be listed now fails the restore instead of restoring the full backup alone. Each incremental is staged in the restore's incremental destination path (default `/tmp/pxb_incrementals`) before it is applied, so that path needs room for the largest incremental in the chain; the last one is left there after the restore.
