Celery beat no longer exits when its database stops answering, for example while PMM Server restarts: it logs the error, keeps sending tasks on the schedule it already has, and picks up schedule changes once the database is back. This matters most in dev mode (`python -m app.main --start-celery`), where nothing restarted beat and every periodic task stopped until the backend was restarted by hand; in the side-car, supervisord no longer has to restart it. Beat still exits if the database is down when beat starts, or if it drops while beat reloads a changed schedule. sqlalchemy-celery-beat is upgraded from 0.8.4 to 0.9.1.
