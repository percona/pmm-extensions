A MySQL Restores task now ends `failed` when an XtraBackup or binlog restore failed for its host; it used to end `success`, with the failure only in the run output. An XtraBackup restore also fails with `Failed to stop MySQL` when MySQL still answers ten minutes after the stop command, where it used to restore anyway. Both take effect on the next run of a restore task after the upgrade: a task that read `success` before can read `failed`, and its failure alert fires.
