A first start of the sidecar no longer exits when PMM's PostgreSQL does not answer within 60 seconds. A start that has to mint its `ENCRYPTION_KEY` (a new installation, or one whose state volume was not mounted) now waits for the three service databases for as long as they do not answer, and logs an `[encryption-key]` line naming the database and the last error at most every 30 seconds. It still refuses to mint, and exits, when a database answers and holds encrypted or undecodable values. A stop signal during the wait now ends the container within a second, with exit status 143. All of this applies from the next container start; see "Starting before PMM is ready" in `sidecar/README.md`.
