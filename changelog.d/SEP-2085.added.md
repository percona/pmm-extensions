Diagnostic script summaries now report whether a script's elevation is never wanted, optional or mandatory, and `GET /api/extensions/hosts/` reports whether a `sudo`-prefixed command can start on each host — able, unable, or never observed — so a client can warn before dispatch instead of after. A host counts as able when its task user is uid 0 or a bare `sudo` resolves on its PATH, which is what the launch check itself requires; it does not promise that user is in sudoers. The host fact is measured by the system-facts sync, which makes it available on different terms per deployment: the PMM-embedded profile collects it daily without operator action, while a standalone install seeds no inventory-sync schedule by default and therefore reports never-observed until a sync is triggered explicitly or an operator attaches an interval. In either profile a host reads never-observed until its first sync completes, and permanently so for an executor host with no inventory match.
