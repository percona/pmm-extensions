Taking a MongoDB backup no longer rewrites PBM's cluster-wide configuration. Applying config is the config task's job alone, and it now merges into the document already on the cluster instead of replacing it, so settings SEP does not model survive an apply. S3 credentials in particular are preserved and stay read-only in SEP: they are changed with the `pbm` CLI on the host.

The MongoDB Backups form no longer asks for storage, point-in-time recovery, or the backup options that describe the deployment rather than the run (node priority, starting-status timeout, oplog span, parallel collections). Those are PBM's cluster-wide configuration and are set on the PBM Configuration tab, which gains a Storage section of its own and an advanced setting for the MongoDB URI credentials path. Creating a backup now asks only what that run decides: compression, selective namespaces, and whether to include users and roles.
