The Operations install pre-check now also refuses a node that cannot resolve the host name of every member of the replica set, including its own, and an Ubuntu node without `curl`. Both used to pass the pre-check and fail later: a member name that does not resolve failed only when the replica set was formed, after every node was installed and then rolled back, and a missing `curl` failed the repository step.

`GET /api/apps/om_bootstrap/runs` accepts `replica_set_name`, returning only the runs that create that replica set. PMM uses it to refuse an install whose replica set name a running install, or one not registered yet, already uses.
