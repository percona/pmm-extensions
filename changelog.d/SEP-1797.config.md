CELERY__BEAT_DBURI now defaults to the resolved PMM Extensions database connection rather than sqlite:///schedule.db, so the celery-beat schedule store follows EXTENSIONS__DATABASE__* — including a password supplied through a mounted secret file, which no longer has to be re-exported inside a credential-bearing URI. An explicit CELERY__BEAT_DBURI from any source still takes precedence and can target a separate store. A deployment that configures a CELERY block without BEAT_DBURI moves its beat schedule from the standalone schedule.db into its PMM Extensions database, and rows already in the old file are not migrated; the bundled development and production_docker profiles set BEAT_DBURI explicitly and are unaffected.
