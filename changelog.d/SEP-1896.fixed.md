An unusable syncer threshold is now rejected when settings load, whichever surface configured it: a SYNCERS entry in settings.yaml, JSON in EXTENSIONS__SYNCERS, or an EXTENSIONS__SYNCER_EXTRA_KWARGS__ env leaf. An unusable STALE_RUN_AFTER or MISSING_GRACE_GENERATIONS value fails startup with the accepted forms named, instead of making every inventory sync trigger return HTTP 500. On upgrade, note that a global SYNCER_EXTRA_KWARGS value for a field none of the configured syncers declares was previously ignored and now blocks startup when it is unusable. Should such a value still reach syncer construction, the sync trigger answers HTTP 503 naming the syncer and the field rather than failing with an unhandled error.
