A failed Operations install step now says why it failed, from the node's own output, instead of "Task history N ended failed"; the pre-check also refuses a node whose port is already taken or that has a `mongod` outside `sudo`'s `PATH` (such as `/usr/local/bin`), and a `mongod` that does not come up reports its journal and log errors. A failed pre-check is no longer retried, a host the install never reached is rolled back as skipped rather than reported as torn down, low free space is reported in GiB with the directory measured, and the scan now measures free space at the data directory the install uses, so the two agree. Rolling back an Ubuntu install now removes `mongod` too: it removed only the `percona-server-mongodb` metapackage, so `mongod`, `mongos`, the tools and `mongosh` stayed and the next install on that node failed its pre-check. On Rocky Linux it no longer relies on the host's `dnf.conf` to remove them.
