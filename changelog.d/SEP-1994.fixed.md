The alerts push no longer decides whether a rule already exists from Grafana's error wording. It now checks the rules actually present in the PMM alert folder, so already-present rules are reported as skipped and stale rules are replaced whatever the upstream message says. When PMM cannot list the folder's rules, the item reports the original rule-creation error instead. A connection to PMM that drops mid-request no longer answers 500 on the Alerts page: a push reports the affected template as an error (or answers 502 when the alert folder itself cannot be read), restore and the PagerDuty save and delete actions answer 502, and the page itself loads with PMM shown as disconnected.
