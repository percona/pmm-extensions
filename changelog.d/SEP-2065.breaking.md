A task syncer's TASK_EXECUTION_TIMEOUT or TASKS_EXECUTION_WAIT_INTERVAL set to zero or a negative number is now rejected when settings load, whichever surface configured it: a SYNCERS entry in settings.yaml, JSON in SEP__SYNCERS, or a SEP__SYNCER_EXTRA_KWARGS__ env leaf. Both previously loaded as bare integers and only reached a constructed syncer, where a zero wait interval polled a running task without ever timing out and a zero timeout declared it timed out without polling it. A deployment configuring either value has to correct it before upgrading: SEP now refuses to start, naming the field and the syncer.
