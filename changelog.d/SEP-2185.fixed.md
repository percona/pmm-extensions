The side-car now starts correctly when its container starts before PMM is ready, which is what a Compose file with a plain `depends_on: pmm-server` produces. With `SECRETS_DIR` set and no `SECRET_KEY` file yet, it waits for PMM to publish the key instead of exiting with advice to generate one. A start that has to mint its Grafana service-account token waits until Grafana answers, instead of giving up after 60 seconds and running without a token until the container was restarted. Neither wait has a bound, and the container log says what the start is waiting for. A start that already holds a token (configured, mounted, or persisted by an earlier start) does not wait. The container now reports unhealthy while it holds no token: during both waits, and after a mint that fails for a reason no wait clears, such as a changed Grafana admin password, where the programs still start. All of this applies from the next container start; see "Starting before PMM is ready" in `sidecar/README.md`.
