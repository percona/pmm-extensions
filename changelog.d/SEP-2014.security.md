Settings-override values typed as credential-bearing URLs now store their embedded password encrypted at rest, by one migration per Alembic track; the surrounding endpoint stays readable. Rolling the code back to an earlier release requires downgrading every track first, because that release reads the stored password as plaintext and would present the ciphertext to the remote as a credential: `alembic --name inventory downgrade -1`, `alembic --name tasks downgrade -1`, and `alembic --name extensions downgrade extensions_main@-1` — the `extensions` track carries several branch heads, so a bare `-1` there downgrades an arbitrary one of them and leaves these rows encrypted.
