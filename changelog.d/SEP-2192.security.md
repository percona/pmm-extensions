The sidecar image's start scripts, settings profile and application code can no longer be renamed, replaced or written by the `extensions` user every process runs as, also when the container is started with the supplementary group 0 as PMM's compose file starts it. `/home/extensions` and `/home/extensions/app` now belong to `root:extensions`, and nothing under the app directory is writable by group or other, so a write there answers `Permission denied`. The sidecar writes only to `/home/extensions/state`, `/tmp`, mounted volumes and `/home/extensions/app/var`, which now holds the Celery worker's state file (`CELERY.WORKER_STATE_DB` in the image's settings profile is now `var/celery_worker_state`). It takes effect when a container is created from an image built from this release; a container that keeps running on an older image keeps the old ownership. See "Volumes" in `sidecar/README.md`.
