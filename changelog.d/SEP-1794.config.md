PMM Extensions can now be served under a URL prefix: the new `EXTENSIONS.ROOT_PATH` setting defaults to `""`, the origin root, while the PMM side-car image ships it as `/extensions`. Artifact download URLs are now joined onto the path of `BASE_URL` / `SNIPPETS_BASE_URL` instead of replacing it, so a base that carries a path keeps it — byte-identical for a path-less base such as `https://host`, and a change of emitted URL for any deployment whose base already carries a path, prefix configured or not. Where a prefix is configured that base must include it: an existing side-car setting `BASE_URL=https://host` must become `https://host/extensions`. PMM Extensions warns at startup, and again where the URL is built, rather than refusing to start — but only when a prefix is set, so a path-carrying base on an unprefixed deployment is worth checking by hand on upgrade. `SESSION_REFRESH.PATH` stays stated relative to the application root and is anchored under the prefix when the cookie is emitted, so it needs no change.
