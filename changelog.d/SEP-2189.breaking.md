The task create and update calls now answer HTTP 422 for a request body that holds a key the call does not declare, and create or change nothing; the error names the key. Until now they answered HTTP 201 or 200 and saved the task without that setting. The calls are `POST` and `PUT /{task_name}` under `/api/apps/mysql_backups/`, `/api/apps/mysql_backups/restore/`, `/api/apps/alters/`, `/api/apps/archives/`, `/api/apps/checksums/`, `/api/apps/backup_mongo/` and `/api/apps/backup_mongo/restore/`; `/api/apps/backup_pg/` already answered this way. A script or API client that sends a key the call does not declare must remove it, or rename it to the field the call's schema lists. PMM's UI sends only declared keys and is not affected.
