Added a list form for `meta.requirements` on task executions: `"requirements": ["PyMySQL", "filelock"]` is accepted alongside the newline-separated string that `run-python` installs, and is joined into that string before the run is stored and dispatched. On any task, a value that is neither a string nor a list of non-empty strings is now rejected with a 422, including one carried by a stored task definition. Task history and schedules stored earlier with such a value still read back unchanged.
