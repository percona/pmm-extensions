Removed deprecated configuration with no compatibility shim. The `EXTENSIONS.PMM` / `EXTENSIONS__PMM__*` section is gone — PMM connection/auth config (`endpoint`, `frontend`, `api_key`, `verify_ssl`, `execution_target`) must now be set under the top-level `PMM` section. The per-syncer `pmm:` override under `SYNCERS` and `SYNCER_EXTRA_KWARGS` is no longer honored; PMM synchronizers read the top-level `PMM` directly. A leftover `EXTENSIONS.PMM` block or per-syncer `pmm:` key is now rejected at startup with a configuration error rather than being silently honored, forcing migration. Alerts-plugin config (`backup_interval`, `backup_retention`, `alert_folder_name`), which previously rode on `EXTENSIONS.PMM`, moves to a dedicated, alerts-owned `EXTENSIONS.ALERTS` section (`BACKUP_INTERVAL`, `BACKUP_RETENTION`, `ALERT_FOLDER_NAME`); it is runtime-overridable (DB-backed settings overrides, exported under `AlertsSettings`). Plugin `MODULE_NAME` values `backup`/`backups` are no longer remapped to `mysql_backups` and now fail module-existence validation — update `settings.yaml` to use `mysql_backups`.
