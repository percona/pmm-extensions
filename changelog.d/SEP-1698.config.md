Diagnostics delivery gains `EXTENSIONS.DIAGNOSTICS_DELIVERY_INPUTS`, an API-overridable key carrying the receiver endpoint and the values of the secrets the configured delivery plan declares, so delivery can be turned on without editing a settings file or restarting; it is written as one whole-object PATCH naming exactly the plan's declared secret names, and per-leaf writes are refused. The Send action becomes available as soon as the write lands, and every send re-reads the stored values before resolving its plan, so turning delivery on, rotating a secret, or repointing the endpoint takes effect for sends enqueued straight afterwards. Inputs that name a secret this deployment's plan does not declare — what a later upgrade renaming a declared secret leaves behind — are reported as no longer matching the plan and needing to be re-supplied, rather than as delivery never having been configured; nothing guesses which old secret name maps to which new one. Such inputs now stop delivery until they are re-supplied, including on a deployment whose plan bakes working credentials of its own, where the stale name was previously ignored and delivery carried on against the baked values. The PMM side-car image now bakes a delivery plan pointing at Percona's production ServiceNow (`percona.service-now.com`) with its credentials empty and allowlists the new key, so no bundle is sent until an operator supplies them; a standalone deployment ships no plan and is unaffected until one is configured.
